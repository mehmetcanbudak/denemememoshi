# Paperclip

> A self-hosted Node.js + React control plane that runs a "company" of bring-your-own AI agents (Claude Code, Codex, OpenClaw, Hermes, Grok Bot, ...) as employees in an org chart, with goal-linked tickets, heartbeat wakeups, per-scope budgets with hard stops, and board approvals. Last verified: 2026-10-20.

Conventions: every non-trivial claim carries an inline source link. `(vendor claim)` = stated by the maker, not verified in code or docs. `[INFERENCE]` = our reasoning, not a sourced fact. `unknown` = searched, not found.

## What it is

Paperclip calls itself "the app people use to manage AI agents for work" and "open-source orchestration for teams of AI agents"; its slogan is "If OpenClaw is an employee, Paperclip is the company" ([README](https://github.com/paperclipai/paperclip#readme)). Concretely it is "a Node.js server and React UI that orchestrates a team of AI agents to run a business. Bring your own agents, assign goals, and track work and costs from one dashboard" ([README](https://github.com/paperclipai/paperclip#readme)).

Mental model: a company. The top-level unit is an organization with a goal ("Build the #1 AI note-taking app at $1M MRR"), employees (every employee is an AI agent), an org structure, a monthly budget in cents and a task hierarchy that traces back to the goal ([core concepts](https://github.com/paperclipai/paperclip/blob/master/docs/start/core-concepts.md)). The human is "the board": sets goals, approves the CEO agent's strategy and hires, and monitors ([delegation guide](https://github.com/paperclipai/paperclip/blob/master/docs/guides/board-operator/delegation.md)). "It looks like a task manager. Under the hood: org charts, budgets, governance, goal alignment, and agent coordination" ([README](https://github.com/paperclipai/paperclip#readme)).

It is explicitly a control plane, not an agent: "Control plane, not execution plane — Paperclip orchestrates agents; it doesn't run them" ([architecture](https://github.com/paperclipai/paperclip/blob/master/docs/start/architecture.md)); "Not an agent framework... Not a prompt manager" ([README](https://github.com/paperclipai/paperclip#readme)). The vision document is maximalist: "the backbone of the autonomous economy... companies [that] collectively generate economic output that rivals the GDP of the world's largest countries" ([doc/GOAL.md](https://github.com/paperclipai/paperclip/blob/master/doc/GOAL.md)) (vendor claim).

Target user: people running many coding/ops agents at once ("You have 20 simultaneous Claude Code terminals open and lose track"), solo operators building "autonomous AI organizations", and increasingly teams/IT (SSO, RBAC, GRC, secrets) per the "four pillars" table ([README](https://github.com/paperclipai/paperclip#readme)). Origin story per press: the lead was running an automated hedge fund with 20+ Claude Code tabs and no shared context or cost tracking ([Towards AI, press](https://pub.towardsai.net/paperclip-the-open-source-operating-system-for-zero-human-companies-2c16f3f22182)).

Relation to the Grok Bot wave: Paperclip predates Grok Bot (launched 2026-08-11) by five months and now treats Grok Bot itself as just another hireable employee: an experimental "Invite external agent → Grok Bot" flow pairs a Bot via a webhook-only Grok routine ([doc/grok-bot-agent.md](https://github.com/paperclipai/paperclip/blob/master/doc/grok-bot-agent.md)). The same pattern exists for OpenAI Dot ([doc/openai-dot-runner.md](https://github.com/paperclipai/paperclip/blob/master/doc/openai-dot-runner.md)) and Meta's personal Muse ([doc/muse-personal-agent.md](https://github.com/paperclipai/paperclip/blob/master/doc/muse-personal-agent.md)), all off by default.

## Product and UX

- **Onboarding.** `npx paperclipai@latest onboard --yes` starts a local instance in trusted loopback mode with embedded Postgres; `--bind lan|tailnet` switches to authenticated mode. `npx paperclipai test-drive` spins up a throwaway instance "already initialized with a CEO agent" for Claude, Codex or OpenCode via an API key. A "Just ask your agent to install Paperclip" path hands the install guide to an existing agent ([README](https://github.com/paperclipai/paperclip#readme)).
- **First loop.** Define the goal, "hire the team" (CEO, CTO, engineers, designers, marketers: "any bot, any provider"), then "Approve and run": review strategy, set budgets, hit go ([README](https://github.com/paperclipai/paperclip#readme)). The CEO wakes, proposes a strategy as an approval, and after approval breaks goals into tasks, assigns reports and submits hire requests ([delegation guide](https://github.com/paperclipai/paperclip/blob/master/docs/guides/board-operator/delegation.md)).
- **Screens** (from docs and release notes): dashboard (spend vs budget per agent), org chart, tasks/inbox with task threads (comments, plans, documents, attachments, run history), approvals queue, costs, routines, activity log, Connections/Apps catalog, Skill Studio, team catalog, Runtime settings per agent ([README](https://github.com/paperclipai/paperclip#readme); [dashboard guide](https://github.com/paperclipai/paperclip/blob/master/docs/guides/board-operator/dashboard.md)). The marketing page shows a budget table per role and agent (e.g. "CTO Codex $0 / $50") ([paperclip.ing](https://paperclip.ing)).
- **Chat is being pulled forward.** In v2026.1012.0 "Chat leads the way": with experimental Agent Chat enabled, Chat is the first row in Work navigation, the chat rail lists every eligible agent, and a side panel shows that agent's recent tasks and artifacts; an experimental "Combined Inbox + Task List" folds inbox into tasks ([release v2026.1012.0](https://github.com/paperclipai/paperclip/releases/tag/v2026.1012.0)). Conversations "hand execution off to linked tasks" ([ROADMAP.md](https://github.com/paperclipai/paperclip/blob/master/ROADMAP.md)).
- **Outside assistants as people.** Same release: Claude Code, Codex, OpenCode or any MCP client can connect "as a signed-in person" via browser OAuth or device code, read/search tasks, create and delegate work, comment, and follow results through signed event webhooks (experimental) ([release v2026.1012.0](https://github.com/paperclipai/paperclip/releases/tag/v2026.1012.0)).
- **Ready-made teams and portability.** Teams with roles, skills, projects and routines can be previewed and installed; whole companies export/import with secret scrubbing ([README](https://github.com/paperclipai/paperclip#readme)). A sibling repo `clipmart` is described as "buy and sell ai-agent companies" ([GitHub org listing](https://github.com/paperclipai)).
- Distinctive: the UX metaphor is corporate rather than messenger. You do not chat with a bot; you file a ticket, an agent checks it out, a reviewer agent or human signs off. Users compare its polish to Linear (third-party testimonial on [paperclip.ing](https://paperclip.ing)).

## Architecture

```
React UI (Vite)  ──HTTP──>  Express API (Node 24)  ──Drizzle──>  PostgreSQL (embedded or external)
                               │  heartbeat scheduler + DB-backed wakeup queue
                               │  budget checks, secret injection, skill loading
                               ▼
              adapters (spawn CLI / call HTTP / Rust Runner over PRP WebSocket)
                               ▼
   Claude Code, Codex, Cursor, Gemini, OpenCode, Pi, Hermes, OpenClaw, Grok, Kimi, ... 
   (local host, SSH target, or sandbox provider)  ──REST calls back──>  Paperclip API
```
(Simplified from [docs/start/architecture.md](https://github.com/paperclipai/paperclip/blob/master/docs/start/architecture.md) and the README "What's Under the Hood" diagram.)

- **Components.** `server/` (Express routes and services), `ui/` (React), `packages/db` (Drizzle schema and migrations), `packages/shared`, `packages/adapter-utils`, `packages/adapters/*` (claude-local, codex-local, cursor-local, cursor-cloud, gemini-local, grok-local, hermes, hermes-gateway, kimi-local, openclaw-gateway, opencode-local, pi-local), `packages/paperclip-runner` (Rust production runner plus TS reference), `packages/plugins/*` (SDK, sandbox providers, LLM wiki, workspace diff), `packages/mcp-server`, `skills/`, `cli/` ([repo tree](https://github.com/paperclipai/paperclip)).
- **Stack.** React 19, Vite 6, React Router 7, Radix UI, Tailwind 4, TanStack Query; Node.js 24.11+, Express 5, TypeScript; PostgreSQL 17 (or embedded) with Drizzle; Better Auth for sessions and API keys; pnpm workspaces ([architecture](https://github.com/paperclipai/paperclip/blob/master/docs/start/architecture.md)). Source builds also compile the Rust Runner ([README](https://github.com/paperclipai/paperclip#readme)).
- **Heartbeat protocol (the core contract).** Agents "don't run continuously — they execute in short bursts called heartbeats". Triggers: schedule, assignment, @-mention comment, manual Invoke, approval resolution ([how agents work](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/how-agents-work.md)). The server resolves the agent's `adapterType`, calls the adapter's `execute()`, which spawns or calls the runtime with injected env vars `PAPERCLIP_AGENT_ID`, `PAPERCLIP_COMPANY_ID`, `PAPERCLIP_API_URL`, `PAPERCLIP_API_KEY` (short-lived JWT), `PAPERCLIP_RUN_ID`, plus wake context (`PAPERCLIP_TASK_ID`, `PAPERCLIP_WAKE_REASON`, `PAPERCLIP_WAKE_COMMENT_ID`, `PAPERCLIP_APPROVAL_ID/STATUS`) ([how agents work](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/how-agents-work.md)). The agent then calls back over REST: `GET /api/agents/me` (role, chain of command, budget), handle approvals, list assignments, `POST /api/issues/{id}/checkout` with `X-Paperclip-Run-Id` (409 = someone else owns it, "Never retry a 409"), read ancestors/comments, work, `PATCH` status with a comment, create subtasks with `parentId` and `goalId` ([heartbeat protocol](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/heartbeat-protocol.md)). The protocol is taught to agents at runtime through the bundled `skills/paperclip` skill ([architecture](https://github.com/paperclipai/paperclip/blob/master/docs/start/architecture.md)). Run "liveness" (`completed`, `plan_only`, `empty_response`, `needs_followup`...) is tracked separately from issue status; only `plan_only`/`empty_response` trigger bounded continuation wakes ([heartbeat protocol](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/heartbeat-protocol.md)).
- **How external agents plug in.** Three tiers: (1) local CLI adapters that spawn the CLI per heartbeat and parse its stream-JSON, or use a native ACP engine (`engine: "acp"`, via `acpx`) for structured `acpx.*` events; (2) gateway adapters that call an already-running service (`openclaw_gateway`, `hermes_gateway`); (3) generic `process` (shell command) and `http` (webhook) adapters ([adapters overview](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/overview.md)). External adapters are npm packages loaded through the plugin system (`POST /api/adapters {packageName}`), e.g. Factory Droid ([adapters overview](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/overview.md)). The newer Rust Runner speaks "PRP v1" over durable WebSocket with replay, and has qualified Codex, OpenCode, ACPX, Claude Managed and AWS AgentCore drivers; local Runners connect over loopback, SSH and sandbox Runners over WSS ([paperclip-runner README](https://github.com/paperclipai/paperclip/blob/master/packages/paperclip-runner/README.md)). Hosted assistants (Grok Bot, OpenAI Dot, Meta Muse) pair through OAuth/pairing codes and receive assignment wakes via the assistant's own routine/webhook or hook mechanism ([grok-bot-agent](https://github.com/paperclipai/paperclip/blob/master/doc/grok-bot-agent.md); [openai-dot-runner](https://github.com/paperclipai/paperclip/blob/master/doc/openai-dot-runner.md)).
- **Models and auth.** Paperclip has no model of its own. Codex uses a host-owned `auth.json` (ChatGPT login) symlinked into a managed `CODEX_HOME` and uploaded to sandboxes, unless a per-agent `OPENAI_API_KEY` is set; Claude uses `ANTHROPIC_API_KEY` / `CLAUDE_CODE_OAUTH_TOKEN` or the sandbox image's own login ([adapters overview](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/overview.md)). Local subscription sign-in needs Python 3 and the provider CLI on the host ([README](https://github.com/paperclipai/paperclip#readme)). DB tables `ai_subscriptions`, `ai_connection_routing`, `ai_connection_defaults` indicate pooled AI connections ([packages/db/src/schema](https://github.com/paperclipai/paperclip/tree/master/packages/db/src/schema)).
- **Execution environment.** Default is the Paperclip host. Sandbox provider plugins: Cloudflare, CreateOS, Daytona, E2B, exe.dev, Kubernetes, Modal, Novita ([packages/plugins/sandbox-providers](https://github.com/paperclipai/paperclip/tree/master/packages/plugins/sandbox-providers)); optional isolated execution workspaces (git worktrees, operator branches) and runtime services such as dev servers with preview URLs ([README](https://github.com/paperclipai/paperclip#readme)).
- **State and storage / data model.** Postgres is the source of truth (embedded locally; "point it at your own Postgres" for production), files on local disk or S3-compatible storage ([README](https://github.com/paperclipai/paperclip#readme)). The schema spans ~170 Drizzle schema files; core tables: `companies`, `agents` (with `agent_config_revisions`, `agent_instruction_revisions`, `agent_api_keys`, `agent_task_sessions`, `agent_runtime_state`), `goals`, `projects`, `issues` (+ `issue_comments`, `issue_documents`, `issue_relations`, `issue_execution_decisions`, `issue_watchdogs`, `issue_work_products`), `heartbeat_runs`, `heartbeat_run_events`, `agent_wakeup_requests`, `approvals`, `cost_events`, `budget_policies`, `budget_incidents`, `routines`, `activity_log`, `company_secrets` (+ versions, bindings), `plugins` ([packages/db/src/schema](https://github.com/paperclipai/paperclip/tree/master/packages/db/src/schema)). Issues carry company/project/goal/parent links, blocker dependencies and atomic checkout with execution locks ([README](https://github.com/paperclipai/paperclip#readme)).
- **Remote and mobile access.** Two runtime modes, `local_trusted` (no login, loopback only) and `authenticated` (private or public exposure), with separate bind presets `loopback | lan | tailnet | custom` ([doc/DEPLOYMENT-MODES.md](https://github.com/paperclipai/paperclip/blob/master/doc/DEPLOYMENT-MODES.md)). Remote access is via Tailscale/VPN or a Docker deployment; there is a `tailscale-https-broker` package ([README](https://github.com/paperclipai/paperclip#readme); [repo tree](https://github.com/paperclipai/paperclip/tree/master/packages)). No relay or pairing app.
- **Extension surface.** Instance-wide plugins with out-of-process workers, capability-gated host services, job scheduling, tool exposure and UI contributions ([README](https://github.com/paperclipai/paperclip#readme)); skills with a Skill Studio, saved test inputs, version history ([README](https://github.com/paperclipai/paperclip#readme)); MCP tool gateway and a public MCP server for assistants ([release v2026.1012.0](https://github.com/paperclipai/paperclip/releases/tag/v2026.1012.0)); REST API for everything; company package import/export ([README](https://github.com/paperclipai/paperclip#readme)). Community index: [awesome-paperclip](https://github.com/gsxdsm/awesome-paperclip).

## Capabilities in detail

- **Org chart and identity.** Agents have adapter type/config, title, reporting line, capabilities text, per-agent monthly budget and status (`active`, `idle`, `running`, `error`, `paused`, `terminated`); "a strict tree hierarchy. Every agent reports to exactly one manager (except the CEO)", used for escalation and delegation ([core concepts](https://github.com/paperclipai/paperclip/blob/master/docs/start/core-concepts.md)). The org chart mixes humans and agents and assigns "responsible-user identities" so delegated work and managed GitHub operations can act as the person directing it ([README](https://github.com/paperclipai/paperclip#readme)).
- **Tickets as the unit of work.** Issues have status `backlog → todo → in_progress → in_review → done` (+ `blocked`, `cancelled`), one assignee at a time, atomic checkout, parent issue and goal links so "agents see the 'why'" ([core concepts](https://github.com/paperclipai/paperclip/blob/master/docs/start/core-concepts.md)). Agents are told to create child issues "instead of polling" and Paperclip wakes the parent when children complete ([heartbeat protocol](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/heartbeat-protocol.md)).
- **Budgets and cost control.** Each heartbeat records provider, model, input/output tokens and cost in cents; budgets exist at company and agent level (`budgetMonthlyCents`), with 80% soft alert ("focus on critical tasks only") and 100% hard stop that auto-pauses the agent until budget is raised or the month rolls over ([costs and budgets](https://github.com/paperclipai/paperclip/blob/master/docs/guides/board-operator/costs-and-budgets.md)). The newer policy table generalizes this: `budget_policies` keyed by `scopeType/scopeId`, `metric` (default `billed_cents`), `windowKind`, `warnPercent` (80), `hardStopEnabled` (true), `reservationCents`, and `unpricedUsagePolicy` defaulting to `"block"` ([budget_policies.ts](https://github.com/paperclipai/paperclip/blob/master/packages/db/src/schema/budget_policies.ts)). Tracking spans company, agent, project, goal, issue, provider and model; the README is candid that "enforcement uses recorded spend; usage reporting and in-flight work can delay a stop" ([README](https://github.com/paperclipai/paperclip#readme)). Unpriced usage is shown as "N run costs unavailable", never as $0; list-price estimates are labeled; late receipts are still accepted ([cost reporting](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/cost-reporting.md)). Hosted assistants (Grok Bot, OpenAI Dot) are flagged as unmetered: "Grok usage and spending are not reported" ([grok-bot-agent](https://github.com/paperclipai/paperclip/blob/master/doc/grok-bot-agent.md)).
- **Approvals and governance.** Approval types `hire_agent` (payload includes proposed adapter config and budget) and CEO strategy; workflow `pending → approved | rejected | revision_requested → resubmitted`; board can pause/resume/terminate any agent, reassign tasks, override budgets, create agents directly ([approvals guide](https://github.com/paperclipai/paperclip/blob/master/docs/guides/board-operator/approvals.md)). Per-issue `executionPolicy` adds ordered review and approval stages whose participants can be agents or users; when the executor marks `done`, the runtime intercepts, moves to `in_review`, reassigns to the reviewer, and records every decision in `issue_execution_decisions`; "comment required" is a runtime invariant ([execution policy](https://github.com/paperclipai/paperclip/blob/master/docs/guides/execution-policy.md)). Config changes are revisioned and can be rolled back ([README](https://github.com/paperclipai/paperclip#readme)). In-thread `request_confirmation` interactions handle yes/no and plan approval bound to a document revision ([heartbeat protocol](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/heartbeat-protocol.md)).
- **Routines and scheduling.** Routines fire on cron, webhook or API, create a tracked issue and wake the assignee, with `concurrencyPolicy` (e.g. `coalesce_if_active`) and `catchUpPolicy` (e.g. `skip_missed`); "agents can only create routines assigned to themselves" ([routines API](https://github.com/paperclipai/paperclip/blob/master/docs/api/routines.md)). Agents also get optional timer heartbeats; "a mention alone does not assign work or wake another agent" ([README FAQ](https://github.com/paperclipai/paperclip#readme)). Wakeups go through a DB-backed queue with coalescing ([README](https://github.com/paperclipai/paperclip#readme)).
- **Memory and context.** Primary memory is the work record: tasks, comments, documents and goal ancestry ([README](https://github.com/paperclipai/paperclip#readme)); adapters serialize session state (e.g. Claude Code session ID) and resume it next heartbeat ([how agents work](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/how-agents-work.md)); recovery hands a fresh conversation a bounded 24,000-byte history handoff ([paperclip-runner README](https://github.com/paperclipai/paperclip/blob/master/packages/paperclip-runner/README.md)). A bundled `para-memory-files` skill gives agents a PARA knowledge graph, daily notes and tacit-knowledge files under `$AGENT_HOME` ([SKILL.md](https://github.com/paperclipai/paperclip/blob/master/skills/para-memory-files/SKILL.md)). Memory/Knowledge is still yellow on the roadmap: experimental connections to Mem0, Zep, Supermemory, Cognee, Honcho plus an LLM Wiki plugin ([ROADMAP.md](https://github.com/paperclipai/paperclip/blob/master/ROADMAP.md)); the design intent is a company-scoped provider binding with per-agent override and provenance back to runs/issues ([doc/memory-landscape.md](https://github.com/paperclipai/paperclip/blob/master/doc/memory-landscape.md)).
- **Multi-agent collaboration.** Through the org chart, not chat: delegation down, escalation up, review stages, blockers, and "Never cancel cross-team tasks — reassign to your manager" ([heartbeat protocol](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/heartbeat-protocol.md)). No multi-agent chat room found; Agent Chat is per agent ([ROADMAP.md](https://github.com/paperclipai/paperclip/blob/master/ROADMAP.md)).
- **Coding.** Project repositories, isolated worktree workspaces, runtime services/preview URLs, workspace diff plugin, verification "from diffs, screenshots & tests" ([README](https://github.com/paperclipai/paperclip#readme); [plugins](https://github.com/paperclipai/paperclip/tree/master/packages/plugins)). Paperclip does not provide an editor or terminal UI.
- **Browser.** Browser Use Cloud connection: delegates website work to Browser Use's hosted agent, embeds its live viewer in the task's Browser tab, API key stays in the vault, per-run max cost settable ([doc/connections/BROWSER-USE.md](https://github.com/paperclipai/paperclip/blob/master/doc/connections/BROWSER-USE.md)).
- **Connectors.** Connections to GitHub, Notion, Railway or your own MCP server; gateway actions set to Allowed, Ask first or Off; "Approve a call once or save a revocable rule"; separate controls for which humans can use a connection and which agents may access it ([README](https://github.com/paperclipai/paperclip#readme)). Catalog discovers accounts already linked in Composio, Arcade and Executor gateways ([release v2026.1012.0](https://github.com/paperclipai/paperclip/releases/tag/v2026.1012.0)).
- **Channels and voice.** Experimental chat/email connectors for Slack, Discord, Telegram and AgentMail ([README](https://github.com/paperclipai/paperclip#readme)); source also contains Microsoft Teams, GitHub, iMessage (Photon) and Speko channel modules ([server/src/services/chat-channels](https://github.com/paperclipai/paperclip/tree/master/server/src/services/chat-channels)). ## Security and trust model

- **Auth modes.** `local_trusted` = no login, loopback; `authenticated` private/public with Better Auth, rate limiting on by default only in public mode; public mode makes local stdio MCP runtimes fail closed ([doc/DEPLOYMENT-MODES.md](https://github.com/paperclipai/paperclip/blob/master/doc/DEPLOYMENT-MODES.md)). Agents authenticate with short-lived run JWTs and agent API keys ([README](https://github.com/paperclipai/paperclip#readme)).
- **Execution isolation.** By default agent CLIs run as the Paperclip host user with that user's subscription logins; isolation is opt-in via sandbox providers and worktrees ([adapters overview](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/overview.md)). A `low_trust_review` preset contains automated work on hostile input (untrusted PRs, external tickets); narrowest policy wins and it fails closed, explicitly "containment, not privacy" ([doc/LOW-TRUST-PRESETS.md](https://github.com/paperclipai/paperclip/blob/master/doc/LOW-TRUST-PRESETS.md)).
- **Secrets.** Company secrets and per-person secret values in encrypted credential storage; runs receive secret references, not values in config; exports omit referenced secret values but "plain environment values and local paths can remain" ([README](https://github.com/paperclipai/paperclip#readme)). AWS secrets provider supported ([doc/SECRETS-AWS-PROVIDER.md](https://github.com/paperclipai/paperclip/blob/master/doc/SECRETS-AWS-PROVIDER.md)).
- **Audit.** Every mutation, heartbeat state change, cost event, approval and comment is recorded in the activity log ([README](https://github.com/paperclipai/paperclip#readme)).
- **Telemetry.** Anonymous usage telemetry is enabled by default; opt out via `PAPERCLIP_TELEMETRY_DISABLED=1`, `DO_NOT_TRACK=1` or config; OpenTelemetry and Sentry are opt-in ([README](https://github.com/paperclipai/paperclip#readme)).
- **Advisory history (serious).** 12 published GitHub security advisories as of 2026-10-20, 5 critical ([security advisories](https://github.com/paperclipai/paperclip/security/advisories)):
  - Unauthenticated RCE on network-exposed `authenticated` instances via an import authorization bypass, chained from open sign-up in six API calls (critical, 2026-04-10, fixed in 2026.416.0) ([GHSA-68qg-g8mg-6pr7](https://github.com/paperclipai/paperclip/security/advisories/GHSA-68qg-g8mg-6pr7)).
  - Drive-by RCE against default `local_trusted` instances via DNS rebinding, because that mode auto-authenticates every request as instance admin and lacked Host header validation (critical, 2026-07-22) ([GHSA-x8hx-rhr2-9rf7](https://github.com/paperclipai/paperclip/security/advisories/GHSA-x8hx-rhr2-9rf7)).
  - Cross-tenant agent API key minting/IDOR (two criticals), OS command injection via workspace `cleanupCommand` (critical), agent-controlled `provisionCommand` privilege escalation, arbitrary file read via `instructionsFilePath`, malicious skills able to exfiltrate data, stored XSS, approval attribution spoofing, unauthenticated endpoints (all 2026-04-16) ([advisories list](https://github.com/paperclipai/paperclip/security/advisories)).
  - "codex_local inherited ChatGPT/OpenAI-connected Gmail and was able to send real email" (high, 2026-04-16): an ambient-credential leak through the wrapped CLI's own connectors ([GHSA-gqqj-85qm-8qhf](https://github.com/paperclipai/paperclip/security/advisories/GHSA-gqqj-85qm-8qhf)).
  - [INFERENCE] The April batch looks like a coordinated audit after the viral launch; the pattern (agent-writable config fields becoming shell commands or file paths, cross-company IDOR) is the predictable failure mode of a control plane whose agents can edit their own configuration through the same API.
- Hosted-assistant integrations admit limits: "Stop Paperclip work" revokes Paperclip authority but "Remote Grok execution may continue"; Grok plugins are account-wide so credentials are not isolated between Bots ([grok-bot-agent](https://github.com/paperclipai/paperclip/blob/master/doc/grok-bot-agent.md)).
- No prompt-injection content was observed in fetched material.

## Strengths

- Clearest governance model in the category: hire approvals, strategy approval, per-issue review/approval stages with agent or human participants, enforced by the runtime rather than by prompt ([execution policy](https://github.com/paperclipai/paperclip/blob/master/docs/guides/execution-policy.md)).
- Only mature budget system seen: scoped policies with warn threshold, hard stop, reservations and an explicit "block on unpriced usage" default, plus honest handling of missing receipts ([budget_policies.ts](https://github.com/paperclipai/paperclip/blob/master/packages/db/src/schema/budget_policies.ts); [cost reporting](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/cost-reporting.md)).
- Truly harness-agnostic: ~12 built-in adapters plus process/http, a plugin path for third-party adapters, and even hosted assistants (Grok Bot, OpenAI Dot, Meta Muse) as employees ([adapters overview](https://github.com/paperclipai/paperclip/blob/master/docs/adapters/overview.md)).
- Robust task semantics: atomic checkout, execution locks, blocker dependencies, parent wake on child completion, liveness continuations, watchdogs ([heartbeat protocol](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/heartbeat-protocol.md)).
- Zero-config start (one `npx`, embedded Postgres) and a path to multi-user, multi-company deployments ([README](https://github.com/paperclipai/paperclip#readme)).
- Huge momentum and ecosystem: ~105k stars, 17k forks, fast release train with four channels.

## Weaknesses and risks

- **Security track record.** Five critical advisories in four months, including unauthenticated RCE and drive-by RCE on default local installs ([advisories](https://github.com/paperclipai/paperclip/security/advisories)). Agents run as the host user with the host's subscription logins by default; the Codex/Gmail incident shows ambient credentials leaking through wrapped CLIs ([GHSA-gqqj-85qm-8qhf](https://github.com/paperclipai/paperclip/security/advisories/GHSA-gqqj-85qm-8qhf)).
- **Complexity.** ~170 Drizzle schema files in `packages/db/src/schema` ([schema](https://github.com/paperclipai/paperclip/tree/master/packages/db/src/schema)), 1,947 npm versions, breaking changes in a stable release requiring all old processes to be drained ([release v2026.1012.0](https://github.com/paperclipai/paperclip/releases/tag/v2026.1012.0)); very dense docs (e.g. the Grok Bot recovery section). [INFERENCE] Heavy for a personal-assistant use case.
- **Wrong default shape for personal assistance.** The corporate metaphor (CEO, board, hires) fits "autonomous business" users; personal-life tasks, chat-first interaction, channels and memory are experimental or roadmap ([ROADMAP.md](https://github.com/paperclipai/paperclip/blob/master/ROADMAP.md)).
- **Budget enforcement is post-hoc.** Stops are based on recorded spend, so in-flight runs can overshoot; hosted assistants and subscription runs are unmetered or priced by estimate ([README](https://github.com/paperclipai/paperclip#readme); [grok-bot-agent](https://github.com/paperclipai/paperclip/blob/master/doc/grok-bot-agent.md)).
- **Maintainer bottleneck and PR backlog.** One pseudonymous lead authors most commits; 3,051 open PRs vs 3,524 merged ([GitHub API](https://api.github.com/repos/paperclipai/paperclip)).
- **Sustainability.** Undisclosed funding, Cloud not launched, hints of an EE split; MIT today, but future paid features may land outside the repo [INFERENCE].
- Telemetry on by default ([README](https://github.com/paperclipai/paperclip#readme)).

## Ideas worth taking for Memoshi

- **Scoped budget policies as data, not prompts:** `scope × metric × window × warn% × hard-stop × unpriced-policy`, applied to company/bot/project/routine; it is the only credible answer to idle token burn for always-on bots ([budget_policies.ts](https://github.com/paperclipai/paperclip/blob/master/packages/db/src/schema/budget_policies.ts)).
- **Default "block on unpriced usage" and never show unknown cost as $0:** honest accounting builds trust when subscriptions and hosted bots do not report spend ([cost reporting](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/cost-reporting.md)).
- **Warn at 80% by telling the bot itself** (agent reads its own budget on wake and narrows to critical work), then auto-pause at 100%; cheap and legible.
- **Go further than Paperclip: pre-run spend estimates and per-run caps** (Paperclip only enforces recorded spend; its Browser Use connector already has a per-run max cost) [INFERENCE].
- **Runtime-enforced review stages:** let a routine or task declare "reviewer: bot X or me", and intercept "done" into "in review"; better than asking the model to remember to ask ([execution policy](https://github.com/paperclipai/paperclip/blob/master/docs/guides/execution-policy.md)).
- **Approval cards bound to a document revision** (`request_confirmation`), and "approve once or save a revocable rule" for tool actions with Allowed/Ask first/Off per action ([README](https://github.com/paperclipai/paperclip#readme)).
- **Hire approval with budget in the payload:** when a bot proposes spawning a helper bot, show role, engine and budget for one-tap approval.
- **Heartbeat contract for BYO agents:** env-var identity + short-lived JWT + REST checkout is a simple, documented way to let any external agent (including Grok Bot or OpenAI Dot) join Memoshi as a teammate ([how agents work](https://github.com/paperclipai/paperclip/blob/master/docs/guides/agent-developer/how-agents-work.md)).
- **Atomic checkout + single assignee** for any shared task list where several bots could pick the same work.
- **Goal ancestry in context:** inject the parent goal chain into every wake so bots know "why" without a memory system.
- **Avoid:** a no-auth `local_trusted` admin mode on a localhost HTTP server (DNS rebinding RCE), agent-writable config fields that become shell commands or file paths, and passing the user's ambient CLI logins/connectors into bots without explicit scoping ([advisories](https://github.com/paperclipai/paperclip/security/advisories)).
- **Avoid the corporate vocabulary for consumers;** keep the mechanics (budgets, reviewers, approvals) but present them as personal-assistant settings [INFERENCE].
