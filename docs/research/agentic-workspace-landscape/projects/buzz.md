Last verified: 2026-10-20.

## What it is

Buzz is "a workspace where humans and agents build together, on a relay you own" ([README](https://github.com/block/buzz#readme)). The mental model is Slack plus a forge: a **community** is reached by URL, and in the self-hosted default one relay URL is exactly one community ([README](https://github.com/block/buzz#what-is-this-really)). Under the hood "it's a Nostr relay: every message, reaction, workflow step, review approval, and git event is a signed event in one log. Same shape, same identity model, same audit trail, whether the author is a person or a process" ([README](https://github.com/block/buzz#what-is-this-really)).

Agents are members, not bots: "Add an agent to a channel the same way you add a person", and agents can open repos, send patches, review code, run workflows, edit canvases, orchestrate other agents, join voice huddles and create channels, "the same affordances as a human teammate, the same audit trail, a different keypair" ([README](https://github.com/block/buzz#what-is-this-really)).

Origin and target user: Block built it after running a Slack-integrated internal agent and hitting the questions "Does everyone get a bot? If people share one, whose credentials does it use?"; "The bottleneck moved from intelligence to coordination" ([engineering post, 2026-07-21](https://engineering.block.xyz/blog/buzz)). Target is engineering teams and open-source projects that want people, agents, code and decisions in one record, on infrastructure they control ([Block announcement](https://block.xyz/inside/introducing-buzz-where-humans-and-agents-work-together)). Block employees use an internal build pre-wired to the Block relay and agent provider ([README](https://github.com/block/buzz#i-work-at-block)), so it is dogfooded.

Timing: Buzz launched 2026-07-21, three weeks **before** Grok Bot (2026-08-11) ([Block announcement](https://block.xyz/inside/introducing-buzz-where-humans-and-agents-work-together)). It is a parallel answer to the same problem from the team-workspace side, not a clone. It later added Grok Build as a harness preset ([presets.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/discovery/presets.rs)).

## Product and UX

- **Surfaces**: Home feed, Stream (Slack-like topic chat, zero-notification default), Forum (Discourse-like async threads), DMs (1:1 and group up to 9), Agents (directory, your agents, job board), Workflows (YAML automation with traces), Search (Cmd+K full-text). "Desktop app supports all seven surfaces today" ([VISION.md](https://github.com/block/buzz/blob/main/VISION.md#surfaces)).
- **Onboarding**: download the desktop app (macOS arm64/x64 DMG, Linux AppImage/deb, unsigned Windows alpha), which connects to `ws://localhost:3000` by default or any relay URL you enter; Block also offers hosted communities at buzz.xyz ([README](https://github.com/block/buzz#i-just-want-to-try-the-app); [release assets](https://github.com/block/buzz/releases/latest)). The desktop generates the user's Nostr key and shows it under Settings > Identity ([self-host post](https://engineering.block.xyz/blog/run-your-own-buzz-relay)).
- **Creating an agent**: the desktop discovers installed ACP runtimes (Goose, Claude Code, Codex, bundled Buzz Agent) plus presets for Pi, Devin, Cursor, Oh My Pi, Grok Build, OpenCode, Kimi Code, Amp, Hermes Agent and OpenClaw, probes their auth status, and defaults new agents to the bundled `buzz-agent` ([catalog.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/discovery/catalog.rs), [presets.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/discovery/presets.rs), [discovery.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/discovery.rs)). Recent releases add Claude effort levels and readable model names in agent create/edit ([CHANGELOG v0.5.27](https://github.com/block/buzz/blob/main/CHANGELOG.md#v0527)).
- **Working with agents**: @mention an agent in a channel or DM; the harness queues mentions per channel, one prompt in flight per channel, and the agent replies through the Buzz CLI/MCP ([buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md)). Edited mentions steer a running turn ([CHANGELOG v0.5.27](https://github.com/block/buzz/blob/main/CHANGELOG.md#v0527)). Owners control a running agent with in-channel commands `!cancel`, `!rotate` (fresh session) and `!shutdown` ([buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md#inbound-author-gate)). Session scope is per channel or per thread ([session_policy.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/session_policy.rs)).
- **Swarm pattern** (distinctive): one frontier agent drives cheaper, faster agents; they coordinate through ordinary mentions "injected into each other's active work almost instantly", and humans redirect while work runs (vendor claim, [engineering post](https://engineering.block.xyz/blog/buzz)).
- **Branch as room**: a feature branch gets a channel where NIP-34 patches, CI results, agent first-pass review and the merge decision land together; the channel archives on merge ([README](https://github.com/block/buzz#three-little-stories); [VISION_PROJECTS.md](https://github.com/block/buzz/blob/main/VISION_PROJECTS.md)). The forge UI shows PRs, review status, branches and activity ([engineering post](https://engineering.block.xyz/blog/buzz)).
- **Other surfaces**: canvases per channel (kind 40100) ([canvas.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/commands/canvas.rs)), channel artifacts such as tasks and projects (NIP-AR, kind 45010) ([NIP-AR](https://github.com/block/buzz/blob/main/docs/nips/NIP-AR.md)), frame-anchored video comments, huddles ([README](https://github.com/block/buzz#a-look-inside)), an owner-only memory panel listing an agent's engrams and their `[[slug]]` link graph ([engrams.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/commands/engrams.rs)), and an admin console for moderation ([CHANGELOG v0.5.28](https://github.com/block/buzz/blob/main/CHANGELOG.md#v0528)).

## Architecture

```
Clients: Buzz desktop (Tauri) | web (served by relay) | Flutter mobile | buzz-cli | buzz-acp -> ACP agents
                 |  WebSocket (NIP-01, NIP-42 auth) + REST (NIP-98 signed HTTP)
                 v
buzz-relay (Axum): EVENT pipeline (verify Schnorr sig + id) -> Postgres events (monthly partitions, FTS)
                   subscriptions/fan-out (Redis pub/sub for multi-node) | audit hash chain | workflow engine
                   /media (Blossom on S3) | /git (Smart HTTP, object-store packs + CAS manifest) | huddle Opus relay
```
Source: [README architecture](https://github.com/block/buzz#architecture), [ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md).

- **Event and identity model**: every action is a NIP-01 event `{id, pubkey, kind, tags, content, sig}` with a secp256k1 key and Schnorr signature; `kind` is the only dispatch switch, so "New feature = new kind number = zero breaking changes" ([ARCHITECTURE.md §2](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#2-the-protocol)). 127 kinds are registered in `crates/buzz-core/src/kind.rs`; Buzz custom kinds sit in 40000-49999 (e.g. 43001 job request, 46001-46012 workflow events, 40100 canvas), ephemeral 20000-29999 kinds (presence, typing) are neither stored nor audited ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#kind-ranges)). Humans and agents get the same thing: keypair, NIP-05 handle, Schnorr auth, with a Bot role on channel membership ([VISION.md](https://github.com/block/buzz/blob/main/VISION.md#identity)).
- **Agent identity and delegation**: Buzz wrote its own NIP drafts where Nostr stopped ([docs/nips](https://github.com/block/buzz/tree/main/docs/nips)):
  - NIP-OA Owner Attestation: an owner key signs a reusable, conditioned `auth` tag authorizing an agent key; the event "remains authored by `event.pubkey`", i.e. authorization does not erase authorship ([NIP-OA](https://github.com/block/buzz/blob/main/docs/nips/NIP-OA.md); [engineering post](https://engineering.block.xyz/blog/buzz)).
  - NIP-AA Agent Authentication: an agent whose owner is a relay member connects by presenting its NIP-OA credential during NIP-42 auth; revoking the owner automatically locks out their agents on next connect ([NIP-AA](https://github.com/block/buzz/blob/main/docs/nips/NIP-AA.md)).
  - NIP-AE engrams (memory), NIP-AP personas and teams, NIP-AR artifacts, NIP-GS git signing with Nostr keys, NIP-FI/NIP-FA federated enterprise identity (issuer JWKS assertions bound to a key) ([NIP-AE](https://github.com/block/buzz/blob/main/docs/nips/NIP-AE.md), [NIP-AP](https://github.com/block/buzz/blob/main/docs/nips/NIP-AP.md), [NIP-GS](https://github.com/block/buzz/blob/main/docs/nips/NIP-GS.md), [NIP-FI](https://github.com/block/buzz/blob/main/docs/nips/NIP-FI.md)).
- **Relay (single source of truth)**: "There is no peer-to-peer event exchange, no gossip, no replication — just clients connecting to one relay" ([ARCHITECTURE.md §1](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#1-executive-summary)). Connection lifecycle: host resolves the community, NIP-42 challenge/response, then recv/send/heartbeat loops; frame cap 64 KiB, 1,024 subs per connection, 500 historical results per filter ([ARCHITECTURE.md §3](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#3-connection-lifecycle)). Multi-community (hosted) mode scopes every row, cache key, search document, workflow, git pointer and audit chain by host-derived community; unknown hosts fail closed ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#step-0-community-binding)). The repo carries TLA+ and Tamarin models for the multi-tenant relay, auth and git-on-object-store ([docs/spec](https://github.com/block/buzz/tree/main/docs/spec)).
- **Tech stack**: Rust 1.88+ workspace (`buzz-core`, `buzz-relay`, `buzz-db`, `buzz-auth`, `buzz-pubsub`, `buzz-search`, `buzz-audit`, `buzz-workflow`, `buzz-acp`, `buzz-agent`, `buzz-dev-mcp`, `buzz-cli`, `buzz-persona`, `git-sign-nostr`, `git-credential-nostr`, `buzz-pair-relay`, `buzz-backend-kubernetes`, `buzz-relay-mesh`, `buzz-voice`, `buzz-push-gateway`, etc.) ([README crate map](https://github.com/block/buzz#architecture); [repo tree](https://github.com/block/buzz/tree/main/crates)). Desktop: Tauri 2, React 19, Vite 8, TipTap 3, TanStack Query, Tailwind 4, `nostr` 0.44 with NIP-44/NIP-49 ([desktop/package.json](https://github.com/block/buzz/blob/main/desktop/package.json), [src-tauri/Cargo.toml](https://github.com/block/buzz/blob/main/desktop/src-tauri/Cargo.toml)). Mobile: Flutter, Riverpod, flutter_secure_storage ([mobile/pubspec.yaml](https://github.com/block/buzz/blob/main/mobile/pubspec.yaml)). Language bytes: Rust 28 MB, TypeScript 15.6 MB, Dart 8 MB ([GitHub languages API](https://api.github.com/repos/block/buzz/languages), 2026-10-20).
- **Agent loop / harness**: `buzz-acp` is the bridge: `Buzz Relay --WS--> buzz-acp --stdio ACP/JSON-RPC--> agent`. It authenticates as the agent key, discovers member channels, queues @mentions per channel, batches queued events into one `session/prompt`, runs a pool of 1-32 subprocesses sharing one identity, respawns on crash, and persists no state ([ARCHITECTURE.md §6](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#buzz-acp--agent-communication-protocol-harness); [buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md)). Turns have an idle timeout (620 s default) and a 2 h hard cap ([buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md#core)). The agent acts back on Buzz via `buzz-cli` ("JSON in / JSON out, designed for LLM tool calls") or the MCP surface ([README](https://github.com/block/buzz#quick-start)). Buzz also ships its own agent: `buzz-agent` (ACP agent, up to 8 concurrent sessions, self-summarizing context) plus `buzz-dev-mcp` (shell, str_replace, todo), designed to be "read in an afternoon" and usable from Zed or JetBrains too ([VISION_AGENT.md](https://github.com/block/buzz/blob/main/VISION_AGENT.md)).
- **Models and auth**: harness-specific; the README's Codex and Claude Code paths use `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` with the codex-acp and claude-agent-acp adapters ([buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md#running-with-codex)). Desktop has model discovery for OpenRouter, Databricks and OpenAI-compatible endpoints ([commands/](https://github.com/block/buzz/tree/main/desktop/src-tauri/src/commands); [CHANGELOG v0.5.28](https://github.com/block/buzz/blob/main/CHANGELOG.md#v0528)). Buzz Mesh pools opted-in members' GPUs (mesh-llm over iroh) and exposes them to agents as a local OpenAI-compatible provider; prompts travel peer-to-peer, not through the relay ([VISION.md](https://github.com/block/buzz/blob/main/VISION.md#buzz-mesh); [engineering post](https://engineering.block.xyz/blog/buzz)).
- **Execution environment**: local managed agents are spawned by the desktop with `~/.buzz` ("nest") as working directory ([managed_agents/mod.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/mod.rs)); the shell tool needs bash (Git Bash on Windows) ([README](https://github.com/block/buzz#windows-prerequisites)). A trusted host can set `BUZZ_ACP_LAUNCH_PREFIX` to wrap workers in a launcher, but "This hook does not enforce a sandbox" ([buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md#host-controlled-launch-wrapper)). Remote agents: the desktop hands a one-way launch payload to a provider binary (Kubernetes first); "after deploy, the desktop retains no substrate control channel", the agent self-reaps after hours of silence, and its key rests as a Kubernetes Secret ([VISION_REMOTE_AGENTS.md](https://github.com/block/buzz/blob/main/VISION_REMOTE_AGENTS.md); [agents_deploy.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/commands/agents_deploy.rs)).
- **State and storage**: Postgres holds events (monthly range partitions), channels, members, workflows, runs, approvals and the audit log; search is a generated `tsvector` column with a GIN index that excludes privacy-sensitive kinds; Redis holds presence (180 s TTL) and typing; media is Blossom on S3 ([ARCHITECTURE.md §8](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#8-infrastructure)). Git repos are immutable content-addressed packfiles plus one mutable manifest pointer advanced by compare-and-swap, model-checked in TLA+ ([engineering post](https://engineering.block.xyz/blog/buzz); [GitOnObjectStore.tla](https://github.com/block/buzz/blob/main/docs/spec/GitOnObjectStore.tla)). Desktop stores nsec keys in the OS keyring as one JSON blob, "the same pattern used by Goose" ([secret_store.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/secret_store.rs)). Mobile treats its store as fully derived from verified events and discardable ([VISION_MOBILE.md](https://github.com/block/buzz/blob/main/VISION_MOBILE.md#architecture)).
- **Remote and mobile access**: clients connect directly to the relay URL; moving an identity to a phone uses an encrypted exchange over Buzz started by a QR secret and confirmed by matching six-digit codes ([engineering post](https://engineering.block.xyz/blog/buzz); `buzz-pair-relay`/`buzz-pairing-cli` crates). A push gateway exists for mobile notifications ([CHANGELOG v0.5.28](https://github.com/block/buzz/blob/main/CHANGELOG.md#v0528)).
- **Extension surface**: ACP for agents, MCP for tools (Buzz's own "full feature surface" MCP server, optional extra MCP server per agent), `buzz-cli`, NIP-01 WebSocket and REST for any client, YAML workflows with webhooks, persona packs, per-runtime skill directories ([VISION.md status](https://github.com/block/buzz/blob/main/VISION.md#status); [buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md#core); [discovery.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/discovery.rs)). Because the wire is Nostr, third-party clients can read the same events [INFERENCE].

## Capabilities in detail

- **Persistent bots and identity**: every agent has its own keypair, profile, presence lease, channel memberships and owner attestation; "Scoped by identity, not by permission flags" ([README](https://github.com/block/buzz#stuff-you-do-in-buzz)). Agent identity is portable: "The same npub can join another community", but agent state is per community ([VISION_AGENT.md](https://github.com/block/buzz/blob/main/VISION_AGENT.md)). Personas (kind:30175: name, avatar, system prompt, model, runtime, name pool) and teams are blueprints; built-in personas ship with the desktop ([NIP-AP](https://github.com/block/buzz/blob/main/docs/nips/NIP-AP.md); [VISION.md](https://github.com/block/buzz/blob/main/VISION.md#agent-personas--teams)). Remote agent restarts are "a resurrection, not a rebirth: fresh compute, same agent" ([VISION_REMOTE_AGENTS.md](https://github.com/block/buzz/blob/main/VISION_REMOTE_AGENTS.md)).
- **Memory**: NIP-AE engrams are addressable `kind:30174` events signed by the agent and NIP-44-encrypted with the agent-owner conversation key, so the owner can always read everything; memory is scoped per (agent, owner) pair; slugs `core` and `mem/...` with `[[slug]]` links ([NIP-AE](https://github.com/block/buzz/blob/main/docs/nips/NIP-AE.md); [engrams.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/commands/engrams.rs)). Durable team knowledge is the searchable channel log itself ([README](https://github.com/block/buzz#stuff-you-do-in-buzz)).
- **Routines and automation**: YAML-as-code workflows per channel; 4 triggers (`message_posted`, `reaction_added`, `schedule` cron, `webhook`) and 7 actions (`send_message`, `send_dm`, `set_channel_topic`, `add_reaction`, `call_webhook`, `request_approval`, `delay` max 300 s); conditions via `evalexpr` with 100 ms timeout; 100 concurrent runs ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#buzz-workflow--yaml-as-code-automation-engine)). Gaps: `send_dm` and `set_channel_topic` return NotImplemented (WF-07) and approval gates fail (WF-08) ([ARCHITECTURE.md §9](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#9-known-limitations)). Agents manage workflows through MCP tools ([VISION.md](https://github.com/block/buzz/blob/main/VISION.md#workflows)). Harness heartbeats fire idle prompts at an interval to check pending approvals and mentions ([buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md#heartbeat-semantics)).
- **Multi-bot collaboration**: agents mention each other in channels and threads; agent-to-agent thread replies stay in thread ([CHANGELOG v0.5.28](https://github.com/block/buzz/blob/main/CHANGELOG.md#v0528)); the README claims agents "orchestrate other agents" and create channels ([README](https://github.com/block/buzz#what-is-this-really)). A benchmark harness `benchmarks/harbor-buzz-orchestra` exists in the repo ([repo tree](https://github.com/block/buzz/tree/main/benchmarks)).
- **Coding workspace**: relay-hosted git over Smart HTTP ("standard `git clone`, `git push`"), pushes signed by your npub, branch protection via kind:30617 rules evaluated in a pre-receive hook (HMAC-authenticated localhost callback; bots are promoted to Member for push, protection rules still apply) ([VISION.md](https://github.com/block/buzz/blob/main/VISION.md#code); [api/git/policy.rs](https://github.com/block/buzz/blob/main/crates/buzz-relay/src/api/git/policy.rs)). NIP-34 patches/repo announcements/status are listed as working ([README](https://github.com/block/buzz#works-today--being-wired-up--strong-opinions-pending-code)). Desktop has project git (branches, diff, merge, push) and a terminal ([commands/project_git*.rs, project_terminal.rs](https://github.com/block/buzz/tree/main/desktop/src-tauri/src/commands)). `BUZZ_GIT_IDENTITY` controls agent commit identity ([CHANGELOG v0.5.27](https://github.com/block/buzz/blob/main/CHANGELOG.md#v0527)). Block calls git "still early" ([Block announcement](https://block.xyz/inside/introducing-buzz-where-humans-and-agents-work-together)).
- **Browser and computer use**: not a Buzz capability; depends on the wrapped harness. A `screenshot_skill.md` ships with managed agents ([managed_agents/](https://github.com/block/buzz/tree/main/desktop/src-tauri/src/managed_agents)).
- **Connectors**: MCP and webhooks; Block says teams can "Connect a database, a CRM, a codebase, or a file system" (vendor claim, [Block announcement](https://block.xyz/inside/introducing-buzz-where-humans-and-agents-work-together)); no curated connector catalog found (unknown).
- **Channels**: Buzz is the chat surface; no Slack/Telegram/WhatsApp bridges evidenced (unknown).
- **Voice**: huddles relay opaque Opus frames over WebSocket inside `buzz-relay`, soft cap 25 peers, no external SFU; recording and per-track publishing not built ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#huddle-audio--websocket-opus-relay)). Desktop has agent STT/TTS, barge-in and push-to-talk modules so agents can speak in huddles ([huddle/](https://github.com/block/buzz/tree/main/desktop/src-tauri/src/huddle); [README](https://github.com/block/buzz#what-is-this-really)).
- **Mobile**: Flutter iOS/Android app with channels, forum, search, profile and pairing, "in active development" ([VISION.md status](https://github.com/block/buzz/blob/main/VISION.md#status)); stated release process targets TestFlight and the internal Comp Portal per RC ([VISION_MOBILE.md](https://github.com/block/buzz/blob/main/VISION_MOBILE.md#release-cycle)). Public store availability: unknown.
- **Team features**: open/private channels, guests scoped to channels, roles (owner, admin, member, bot), staff ban/timeout/delete, admin console across communities, hosted multi-tenancy with community archive/deletion flows ([VISION.md](https://github.com/block/buzz/blob/main/VISION.md#access); [CHANGELOG](https://github.com/block/buzz/blob/main/CHANGELOG.md)).

## Security and trust model

- **Signed everything**: every event's Schnorr signature and SHA-256 id are verified before storage ([ARCHITECTURE.md §7](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#7-security-model)). Auth is NIP-42 (WebSocket, ±60 s) or NIP-98 (signed HTTP); AUTH events are never stored or audited ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#authentication)).
- **Audit**: `buzz-audit` is an append-only SHA-256 hash chain per community over seq, timestamp, event id, kind, actor pubkey, action, channel and canonical metadata, with a single-writer advisory lock and `verify_chain()`; 10 actions (event created/deleted, channel and member changes, auth success/failure, rate limit) ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#buzz-audit--hash-chain-audit-log)).
- **Access control**: "Channel membership is the only gate", checked before subscription registration; NIP-42 grants all 14 scopes, so finer scopes are not used on WebSocket auth ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#buzz-auth--authentication-and-authorization)).
- **Agent inbound gate**: `buzz-acp` defaults to `--respond-to owner-only`; modes allowlist/anyone/nobody; owner control commands bypass the gate ([buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md#inbound-author-gate)). A build flag can clamp all managed agents to owner-only at local spawn and remote deploy ([access_policy.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/access_policy.rs)).
- **Tool permissions**: `buzz-acp` answers every ACP `session/request_permission` by auto-selecting `allow_once` (fallback `reject_once`) ([acp.rs](https://github.com/block/buzz/blob/main/crates/buzz-acp/src/acp.rs)); the Grok Build preset launches with `--always-approve` ([presets.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/discovery/presets.rs)); README quick start sets `GOOSE_MODE=auto` ([buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md#quick-start-goose)). `buzz-agent` asks for every MCP tool call and refers to a client-side `BUZZ_ACP_PERMISSION_POLICY` ([permission.rs](https://github.com/block/buzz/blob/main/crates/buzz-agent/src/permission.rs)), but GitHub code search finds that name only in that file (2026-10-20). [INFERENCE] In practice agents run with the operator's full shell rights on the host; safety rests on identity scoping, owner-only gating and audit, not per-action human approval.
- **Approvals**: the workflow `request_approval` action still marks runs Failed with `approval_not_supported ... see WF-08` at HEAD ([buzz-workflow/src/lib.rs](https://github.com/block/buzz/blob/main/crates/buzz-workflow/src/lib.rs)), even though DB tables, REST grant/deny endpoints, MCP tool and UI exist ([VISION.md](https://github.com/block/buzz/blob/main/VISION.md#workflows)). Approval tokens are CSPRNG UUIDs stored hashed and single-use ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#access-control)).
- **Sandboxing**: none by default; the launch-prefix hook is the integration point for a host-supplied sandbox ([buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md#host-controlled-launch-wrapper)). Remote agents' keys rest as Kubernetes Secrets readable by anyone the cluster trusts in that namespace (stated in [VISION_REMOTE_AGENTS.md](https://github.com/block/buzz/blob/main/VISION_REMOTE_AGENTS.md#honest-costs)).
- **Encryption**: channels and DMs are server-readable by design: "Server-managed encryption covers every channel, every DM, every event — eDiscovery works on everything. End-to-end encryption (NIP-44) is a future consideration for DMs" ([VISION.md](https://github.com/block/buzz/blob/main/VISION.md#encryption)). Engrams, agent live telemetry/cancellation and cost records are encrypted so "the server sees routing metadata, not those payloads" (vendor claim, [engineering post](https://engineering.block.xyz/blog/buzz)).
- **Known gaps** listed by the maintainers: no rate limiting is enforced (only a test stub; four tiers designed for human/agent classes); inbound workflow webhooks compare the stored UUID secret directly rather than an HMAC of the body ([ARCHITECTURE.md §7, §9](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#9-known-limitations)). SSRF guard is an enumerated deny list that accepts unlisted classes such as `fe00::1` ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#ssrf-protection)).
- **Key custody**: losing a private key means losing the identity, with no recovery flow (stated in [VISION_SOVEREIGN.md](https://github.com/block/buzz/blob/main/VISION_SOVEREIGN.md#what-you-give-up)); desktop offers HPKE key backup ([hpke_key_backup.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/hpke_key_backup.rs)). Relay key rotation invalidates everything the relay previously signed ([self-host post](https://engineering.block.xyz/blog/run-your-own-buzz-relay)).
- **Telemetry**: no analytics SDK found in desktop dependencies ([desktop/package.json](https://github.com/block/buzz/blob/main/desktop/package.json), [src-tauri/Cargo.toml](https://github.com/block/buzz/blob/main/desktop/src-tauri/Cargo.toml)); relay exposes Prometheus metrics and the Helm chart carries Datadog labels ([ARCHITECTURE.md §8](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#services); [CHANGELOG v0.5.28](https://github.com/block/buzz/blob/main/CHANGELOG.md#v0528)). Third-party press says no telemetry leaves a self-hosted perimeter (third-party, [Open Source For You](https://www.opensourceforu.com/2026/07/block-unveils-buzz-an-open-source-workspace-built-for-human-agent-parity/)).
- **Incidents/advisories**: no published GitHub security advisories (API, 2026-10-20); private reporting with 48 h acknowledgment target ([SECURITY.md](https://github.com/block/buzz/blob/main/SECURITY.md)).

## Strengths

- One substrate for chat, automation, code, approvals and audit: a single signed event shape, one search index, one identity model ([README](https://github.com/block/buzz#why-buzz-is-better)).
- The most rigorous agent-identity design in the category: separate agent keys, owner attestation that preserves authorship, revocation by removing the owner, all written up as NIP drafts with test vectors ([NIP-OA](https://github.com/block/buzz/blob/main/docs/nips/NIP-OA.md), [NIP-AA](https://github.com/block/buzz/blob/main/docs/nips/NIP-AA.md)).
- Harness-agnostic via ACP with 14 runtime entries, including Grok Build, Claude Code, Codex, OpenCode, Hermes and OpenClaw ([presets.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/discovery/presets.rs)).
- Real self-hosting story: one Rust binary plus Postgres/Redis/S3, production Compose with Caddy, Helm charts, Railway button, five-item backup list ([self-host post](https://engineering.block.xyz/blog/run-your-own-buzz-relay)).
- Unusual engineering discipline: formal TLA+/Tamarin models, an honest "Known Limitations" table, documented honest costs ([ARCHITECTURE.md §9](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#9-known-limitations); [docs/spec](https://github.com/block/buzz/tree/main/docs/spec)).
- Corporate backing, internal dogfooding at Block, very high commit velocity ([README](https://github.com/block/buzz#i-work-at-block); GitHub API).

## Weaknesses and risks

- **Human-in-the-loop is thin today**: ACP tool calls are auto-approved and workflow approval gates fail at HEAD ([acp.rs](https://github.com/block/buzz/blob/main/crates/buzz-acp/src/acp.rs); [buzz-workflow/src/lib.rs](https://github.com/block/buzz/blob/main/crates/buzz-workflow/src/lib.rs)). No sandbox by default.
- **No E2E encryption** for channels or DMs, by design (eDiscovery). Fine for enterprises, wrong for a personal assistant handling private life data [INFERENCE] ([VISION.md](https://github.com/block/buzz/blob/main/VISION.md#encryption)).
- **No rate limiting enforced**, which matters for agent-generated write volume ([ARCHITECTURE.md §9](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#9-known-limitations)).
- **Key-management UX tax**: unrecoverable keys, relay URL becomes community identity (changing it starts a new empty community) ([VISION_SOVEREIGN.md](https://github.com/block/buzz/blob/main/VISION_SOVEREIGN.md#what-you-give-up); [self-host post](https://engineering.block.xyz/blog/run-your-own-buzz-relay)).
- **Team/engineering product, not a personal assistant**: no inbound channels (email, SMS, WhatsApp), no browser/computer use of its own, no per-bot computer for local agents [INFERENCE from capability list].
- **Complexity and churn**: ~30 crates, 127 event kinds, a dozen custom NIPs, 1,981 open PRs; contributors outside Block are few; much of the scope (mesh, remote agents, forge) is still "vision" ([VISION.md status](https://github.com/block/buzz/blob/main/VISION.md#status)).
- **Platform tie to Nostr**: interop is a feature, but custom kinds and NIP drafts are Buzz-specific, so "portable" history is portable mainly to other Buzz relays today [INFERENCE].
- **Windows build unsigned** ([README](https://github.com/block/buzz#i-just-want-to-try-the-app)).

## Ideas worth taking for Memoshi

- **Signed append-only event log as the single record** of messages, tool calls, approvals, automation runs and git events: one schema gives search, audit, replay and sync for free ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#2-the-protocol)). Adopt even without Nostr: a `kind` integer plus signed JSON keeps new features additive.
- **Unified identity for humans and bots**: every bot gets its own keypair and profile instead of borrowing the user's credentials; the owner signs a scoped, expiring delegation and the bot remains the author (NIP-OA semantics). Gives clean attribution and per-bot revocation ([NIP-OA](https://github.com/block/buzz/blob/main/docs/nips/NIP-OA.md)).
- **Owner-revocation cascade** (NIP-AA): bots inherit access from their owner's membership, so removing a user disables all their bots automatically ([NIP-AA](https://github.com/block/buzz/blob/main/docs/nips/NIP-AA.md)).
- **Hash-chained audit log** next to the event store, cheap to implement and verifiable ([ARCHITECTURE.md](https://github.com/block/buzz/blob/main/ARCHITECTURE.md#buzz-audit--hash-chain-audit-log)).
- **Owner-encrypted bot memory** (engrams): memory belongs to the (bot, owner) pair, encrypted so only those two can read it, with linkable slugs and an owner UI to inspect it ([NIP-AE](https://github.com/block/buzz/blob/main/docs/nips/NIP-AE.md)).
- **Default "owner-only" response gate** plus in-chat control verbs (`!cancel`, `!rotate`, `!shutdown`) that bypass the model ([buzz-acp README](https://github.com/block/buzz/blob/main/crates/buzz-acp/README.md#inbound-author-gate)). Cheap, legible safety.
- **Mention-to-steer**: edits or new mentions inject into a running turn instead of queuing, so humans redirect live work ([CHANGELOG v0.5.27](https://github.com/block/buzz/blob/main/CHANGELOG.md#v0527)).
- **ACP as the harness boundary** with a runtime catalog and auth-status probing, plus a small bundled default agent so first run works without installs ([discovery.rs](https://github.com/block/buzz/blob/main/desktop/src-tauri/src/managed_agents/discovery.rs)).
- **"Relay is the only tether" for cloud bots**: one-way deploy handoff, presence as a renewable lease, self-reaping after inactivity, identity and memory outliving disposable compute ([VISION_REMOTE_AGENTS.md](https://github.com/block/buzz/blob/main/VISION_REMOTE_AGENTS.md)). Good model for Memoshi's per-bot computers.
- **Avoid**: auto-approving tool permissions and shipping approval UI before the executor can suspend/resume; Memoshi should make durable suspend/resume of approvals a day-one primitive (Buzz's WF-08 gap shows it is easy to defer and hard to retrofit) [INFERENCE].
- **Avoid for personal data**: server-readable DMs; Memoshi's personal-assistant side likely needs E2E or local-only storage for private threads [INFERENCE].
