## 0. Bottom line

1. **Keep the D6 package set, pinned at exactly 1.3.0.** `v1.3.0` (2026-10-15) is still the newest [release](https://github.com/earendil-works/pi/releases/tag/v1.3.0) and the npm `latest` of every maintained Pi package on 2026-10-20 (§2). `pi-durable` is the execution root, `pi-ai` supplies models, `pi-codemode` runs through `pi-durable/codemode`, `pi-mcp` is a client whose tools Memoshi wraps, and `pi-env` serves every computer. `chord` and `pi-telemetry` arrive transitively.
   - **Update 2026-10-22:** v1.4.0 was released on 2026-10-21, so 1.3.0 is no longer the newest release. Moving to 1.4.0 is a decision, not a refresh: SQLite stores migrate on open and cannot roll back, and durable lists six breaking changes ([follow-ups §7](2026-10-22-viticci-followups.md#7-following-upstream-pi)).
2. **Never build Pi from `main` for Memoshi.** `main` carries unreleased breaking changes while every `package.json` still says `1.3.0`. One of them migrates SQLite storage to a schema that "cannot be opened by 1.3.0 or earlier" (§7). Pin by npm integrity hash, not by version string.
   - **Update 2026-10-22:** the schema-2 migration is now part of the released 1.4.0. The rule stands: build only from released, integrity-pinned packages.
3. **Pi is the engine, not the product.** It verifiably supplies durable transcripts, documents and tasks; `requestId` deduplication; tool tasks that commit intent before executing, with a replay policy; blocking hooks that also see nested Code Mode and MCP-bridge calls; deterministic Code Mode replay; deferred tools; prompt sections rendered per request; compaction; usage and cost; subagent ownership; in-process views; an SSH/PTY execution daemon; and an MCP client with OAuth. It verifiably does **not** supply a permission policy, approvals or Cards, a calendar scheduler, memory, a context-file loader, conversation deletion, cross-process locking, a network UI protocol, sandboxing, exactly-once external effects, or any Apple capability (§6).
4. **Adopt no ecosystem extension as a dependency.** Gondolin is a design source for egress control and secret placeholders. `pi-durable-components` is a reference only. `pi-claude-code`, `pi-voice`, `pi-chat`, Radius and Earendil's private web UI are out (§2.2).
5. **Auth stays API keys and local endpoints (D10).** pi-ai 1.3.0 ships OAuth sign-in modules for Anthropic (whose request path adds a "You are Claude Code" system block for OAuth tokens), Meta (the Muse Code CLI client id), xAI (`grok-cli:access` scope), OpenAI ChatGPT and Codex, GitHub Copilot, Kimi Coding, OpenRouter and Radius. It ships no Google module. D10 names Google, which Pi does not ship, and omits xAI, which it does (§5.2).
6. **Three verified facts the plan has not fully absorbed** (§4.12, §4.3, §5.1): scheduling is per Harness, so any `submit`, `abort`, `compact` or wait call resumes *all* recovered work in that storage file; a lost pi-env connection leaves in-flight mutations with an unknown outcome, and pi-env has no detach feature; none of the seven published tarballs checked contains a LICENSE file.

## 3. What each package is for

**pi-durable: the execution root.** "A durable agent harness. Conversations, model turns, tool calls, and your own state are committed to storage before anything is shown. If the process dies mid-turn, reopening the storage picks the work up where it stopped" ([README L5](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L5)). Its concepts are Harness, Conversation, Entry, Commit, Document, Task, Submission, run, Extension, Registry and Agent ([L80–L101](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L80-L101)). Subpath exports: `env`, `env/node`, `codemode`, `tool-search`, `tools`, `images`, `storage/{memory,jsonl,sqlite}` with Node and Cloudflare variants, and `testing` ([package.json](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/package.json)). It depends on chord, pi-ai, pi-codemode, Photon (WebAssembly, loaded only when imported), `diff` and TypeBox, but not on pi-mcp or pi-env. Its root import "costs about 23 MB of peak RSS unbundled, about 4 MB in a tree-shaken bundle" ([L709](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L709)). The announcement puts the source at "about 15,000 lines" (vendor claim).

**pi-ai: models.** A `Models` collection of providers; "Every provider owns its auth"; a `CredentialStore` the host injects; `createProvider()` for local OpenAI-compatible servers with keyless auth; a faux provider for tests; usage and cost on every message ([README](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/README.md), sections "Auth", "Custom Providers", "Faux Provider for Tests"). Provider factories are separate subpath imports, and "With code splitting, provider SDKs stay in lazy chunks" ([L1636–L1654](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/README.md?plain=1#L1636-L1654)).

**pi-agent-core: the in-memory loop, kept as D6's fallback.** "Stateful agent with tool execution and event streaming" ([README L3](https://github.com/earendil-works/pi/blob/v1.3.0/packages/agent/README.md?plain=1#L3)). It has blocking `beforeToolCall`/`afterToolCall` hooks, `prepareRequest` to "install canonical persisted context", and steer and follow-up queues ([L118–L146](https://github.com/earendil-works/pi/blob/v1.3.0/packages/agent/README.md?plain=1#L118-L146)). It persists nothing itself, so falling back to it means rebuilding durability in Memoshi, which is what D6 already budgets.

**pi-coding-agent: the CLI, not the brain.** It depends on pi-agent-core, pi-ai, pi-codemode, pi-mcp and pi-tui, and **not** on pi-durable ([package.json](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/package.json)). Its sessions are its own entry trees owned by `SessionManager` ([sdk.md L36–L58](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/sdk.md?plain=1#L36-L58)), so it cannot share a conversation with a Durable Harness. It is useful as a developer tool and as the source of conventions such as context-file discovery, which [07-coding](../plan/07-coding.md) already reimplements. Its RPC mode is a JSONL protocol over stdio ([rpc.md L22–L33](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/rpc.md?plain=1#L22-L33)).

**pi-codemode: the script sandbox.** QuickJS (`quickjs-wasi`) in "a worker thread per execution"; scripts get `tools.*`, `ALL_TOOLS`, globals, `store`/`load`, and "Nothing else: no timers, `fetch`, `process`, `require`, modules, or `WebAssembly`" ([README L11, L47–L56](https://github.com/earendil-works/pi/blob/v1.3.0/packages/codemode/README.md?plain=1#L11-L56)).

**pi-mcp: a standalone MCP client.** "It does not depend on the official MCP SDK or other pi packages"; stdio and Streamable HTTP transports; an OAuth subset ([README](https://github.com/earendil-works/pi/blob/v1.3.0/packages/mcp/README.md)). Turning MCP tools into Durable tools is the host's job (§4.6).

**pi-env: remote execution.** "An agent's tools run on another machine, usually over SSH, while the Durable worker, its storage and credentials stay local." A Rust daemon speaks a framed stdin/stdout protocol; `RemoteExecutionEnv` is a Durable `ExecutionEnv` whose "results match `NodeExecutionEnv` running on the remote machine; only error messages may differ" ([README L3–L10](https://github.com/earendil-works/pi/blob/v1.3.0/packages/env/README.md?plain=1#L3-L10)). The package ships prebuilt daemons for Linux, macOS, Android and Windows on x64 and arm64.

**chord, pi-telemetry, pi-tui.** Chord supplies `Context` (cancellation), `replicatedState` (which Durable uses for views) and links over memory, Node IPC or WebSocket ([README L3–L21, L100–L102](https://github.com/earendil-works/pi/blob/v1.3.0/packages/chord/README.md?plain=1#L3-L21)). pi-telemetry defines vendor-neutral span and metric contracts; pi-ai 1.3.0 already depends on it. pi-tui is the terminal renderer and is not used.

## 4. Runtime semantics Memoshi relies on (verified against 1.3.0)

### 4.1 Persistence and storage

| Backend | Guarantee as documented |
|---|---|
| SQLite (`openNodeSqliteStorage`) | "One database file. WAL mode with `synchronous = NORMAL`: commits survive process crashes; the newest may be lost on power or host failure." Uses `node:sqlite` `DatabaseSync` (`dist/storage/sqlite/node.js`) |
| JSONL | Append-only; optional `fsync`; "Keeps the whole history in memory too … use SQLite for long-running agents" |
| Memory | "Nothing is persisted" |
| Cloudflare Durable Object | The object's SQLite storage |

- Source: [Storage, L656–L709](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L656-L709). "One process owns a storage at a time; there is no cross-process locking" (L682).
- Partial answers and tool output "are committed at most every 100 ms by default, so a crash loses at most that window" ([L406](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L406)).
- 1.3.0 adds a `prefix` option so Pi can share a database with host tables ([CHANGELOG L7](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/CHANGELOG.md?plain=1#L7)). The README describes a shared operation queue only for the Cloudflare adapter, so Memoshi's separate files ([04 §4.2](../plan/04-architecture.md#42-harness-pool-and-storage-backend)) remain the safer reading [INFERENCE].
- No API deletes or purges a conversation: none appears in the published types, and the spec says compaction "does not delete transcript history" ([spec L3745–L3746](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L3745-L3746)). Per-thread files ([04 A1](../plan/04-architecture.md#0-what-this-document-adds-to-the-contract)) remain the only way to delete a thread.

### 4.2 Submissions and busy conversations

- "A retried submission with the same `requestId` returns the existing submission instead of submitting twice" ([L117–L126](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L117-L126)). The announcement words it as "A `requestId` makes a submission exactly-once" (vendor claim); this covers admission, not external effects.
- While a run is busy: steers join "after the current tool round"; follow-ups start the next run; a write of only `kind` and `data` "is appended at once, even mid-run"; a write with `model`, `head` or `edits` "waits for the next boundary like a steer"; `whenBusy: "reject"` throws ([Busy Conversations, L408–L441](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L408-L441)).
- `root()` creates the root once; when it exists, "`agent` and `init` are ignored and no write occurs" ([spec L661–L665](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L661-L665)).

### 4.3 Replay and unsafe side effects

- **Tools:** "Its intent is committed before `execute()` runs. If the process dies mid-call, the tool reruns on reopen only when it is declared `replay: "safe"`; otherwise the model gets an `interrupted` error result with the output committed so far" ([L181](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L181)). "Omitted `replay` is `unsafe`" ([spec L2927](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L2927)), implemented as `replay: tool.replay ?? "unsafe"` ([tool.ts L169](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/src/harness/tool.ts#L169)). The built-in `read`, `write`, `edit` and `bash` declare no policy, so they are unsafe; `codemode` and `tool_search` are `replay: "safe"` (checked in `dist/tools/*.js`, `dist/codemode/codemode.js`, `dist/tool-search/tool-search.js`).
- **Model requests:** recovery "converts a committed partial left in `pi.live` by an interrupted attempt into an aborted `pi.assistant` entry" and then streams again ([spec L4001–L4005](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L4001-L4005)). A crash therefore costs a repeated provider call, which the budget gate must count [INFERENCE].
- **Nested calls:** a replay-safe caller that reruns "gets the nested calls it already made back"; "A nested call the crash interrupted before its result was committed follows its own `replay` policy, so a replay-safe tool with external effects still needs its own idempotency"; a caller that is not replay-safe "never reruns, so after a restart its unfinished nested calls are abandoned" ([L232](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L232); "This is not exactly-once execution", [spec L2981–L2984](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L2981-L2984)).
- **Hooks:** "a crash before the consuming commit may rerun them" ([spec L2689–L2690](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L2689-L2690)); once intent is recorded, "Recovery does not rerun `beforeTool`" ([spec L3231–L3233](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L3231-L3233)).
- **Remote execution:** "Requests in flight when [the connection] is lost fail with code `unknown`; for mutations their outcome is then unknown" ([connection.ts L179](https://github.com/earendil-works/pi/blob/v1.3.0/packages/env/src/connection.ts#L179)). The daemon "kills every process group it started and exits after 30 seconds without receiving any bytes, or when stdin ends. A dropped connection therefore stops remote commands" ([protocol.md L62–L67](https://github.com/earendil-works/pi/blob/v1.3.0/packages/env/docs/protocol.md?plain=1#L62-L67)). No detach feature exists in pi-env 1.3.0's JavaScript, type declarations or docs (searched). Work that must outlive a link is detached by the host with OS tools, as [06 §4.6](../plan/06-computers-and-browsers.md) plans with `systemd-run --user`.
- **Conclusion:** Pi gives at-most-once execution for unsafe tools and at-least-once for safe ones. It never gives exactly-once external effects. The effects ledger, idempotency keys and Resume cards of [D42](../plan/decisions.md#d42) and [04 §4.11](../plan/04-architecture.md#411-replay-and-idempotency) remain Memoshi's job.

### 4.4 Tool hooks, including nested Code Mode and MCP calls

| Hook | Composition | Ordinary throw |
|---|---|---|
| `beforeRequest` | replacement chain | report, continue |
| `afterResponse` | all observers | report, continue |
| `onYield` | first continuation wins | report, continue |
| `beforeTool` | argument replacement chain; first block wins | **block** the tool with error text |
| `afterTool` | result replacement chain | **report, continue** |
| `afterTools` | all observers | report, continue |
| `beforeCompact` | first decision wins | report, continue |

Source: [spec §7.2, L2681–L2703](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L2681-L2703).

- `beforeTool` runs "before intent" and may replace arguments or block; arguments are validated before and after it ([spec L2736–L2750](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L2736-L2750), [L3227–L3229](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L3227-L3229)).
- **Nested calls are policed.** A nested call "is its own `pi.tool` task … runs the whole tool pipeline … including the `ToolTask` hooks, which see `call.parent`" ([spec L2932–L2943](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L2932-L2943)); "Hooks see a nested call's `call.parent`, so a guard can treat calls from scripts differently" ([README L230](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L230)). Code Mode's `tools.<name>()` calls are nested calls, so one policy covers scripts ([D9](../plan/decisions.md#d9)).
- **MCP has no built-in Durable bridge.** pi-durable does not depend on pi-mcp. The README's "MCP bridge" is a pattern: a host tool that calls `api.executeTool()`. In Memoshi's design each MCP tool is wrapped as its own Durable tool ([04 §4.8](../plan/04-architecture.md#48-mcp-through-pi-mcp)), so a model's call is a top-level tool task and a script's call is a nested one. Both pass `beforeTool`.
- **What a hook can do:** `HookApi` gives committed reads, `models`, and task memos; it has no commit ([spec L2708–L2716](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L2708-L2716)). "Hooks use task memos for durable first-writer-wins decisions" (L2702), and memos "survive checkpoints" (L1947–L1950). Hooks share the task's memo namespace, "so hook authors prefix their memo names" (L2781–L2782). The vendor's own approval example stores the decision in a memo inside `beforeTool` ([announcement, "Hooks"](https://earendil.com/posts/pi-durable/)), which is the pattern of [04 A3](../plan/04-architecture.md#0-what-this-document-adds-to-the-contract).
- **`afterTool` must not throw.** A throw is reported and the chain continues, so a scrubber that throws lets the unscrubbed result through. "An `afterTool` hook that redacts a schema tool's `output` must redact its `structuredOutput` too" ([README L199](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L199)).
- **Who may call what:** `callers` (`model`, `tools` or both), `modelTools`, and `deferred` tools that the model sees only after `tool_search` loads them ([L237–L253](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L237-L253)). "Nothing bounds how deeply calls nest" (L235).
- **Long transactions:** "Never await models, tools, processes, network calls, humans … inside" a commit callback ([spec L5255–L5257](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L5255-L5257)). An approval wait belongs in the hook, never inside `commit()`.
- **No watchdog found:** the 1.3.0 spec has a stream timeout for model requests but no limit on how long a hook may wait (searched "timeout", "deadline", "watchdog"). Long approval waits still need the S1 test ([04 open question 1](../plan/04-architecture.md#open-questions)).
- **Other Pi runtimes behave alike:** in the coding agent, nested calls "go through argument validation and the `tool_call` and `tool_result` handlers like model-issued calls" ([extensions.md L149](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/extensions.md?plain=1#L149)), and "A `tool_call` handler failure blocks the tool as a fail-safe" ([L263](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/extensions.md?plain=1#L263)). pi-agent-core's Code Mode example routes calls through `runToolCall()` "so `beforeToolCall` and `afterToolCall` apply to those calls too" ([agent README L506–L508](https://github.com/earendil-works/pi/blob/v1.3.0/packages/agent/README.md?plain=1#L506-L508)).

### 4.5 Code Mode

- `pi-durable/codemode` adds a `codemode` tool with `callers: ["model"]` and `replay: "safe"` ([codemode.ts L239–L240](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/src/codemode/codemode.ts#L239-L240)). "The script survives a restart: it resumes where it was, without running its finished calls again" ([README L259–L272](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L259-L272)).
- Mechanism: a deterministic VM ("a virtual clock, seeded randomness, UTC") plus a journal written before each delivery. A rerun fails "when the script takes another path than before, when the sandbox's fingerprint or the code mode version changed, or when its `timeout_ms` passed meanwhile" (same section). Memoshi's quiesce-before-update step ([04 §2.5](../plan/04-architecture.md#25-updates)) follows from this.
- Options in the published types: `sandbox`, `namespaces`, `inlineBudget` (default 3000) and `models` (**default true**: scripts get the model catalog, classifiers and image generation as nested calls of internal tools) (`dist/codemode/codemode.d.ts`). Memoshi's `models: false` ([04 §4.7](../plan/04-architecture.md#47-code-mode)) removes an unpreviewed spend path.
- Sandbox: each execution starts a worker thread "(about 20 ms including VM creation)" with a fresh QuickJS instance whose only imports are a WASI shim and one host-call entry point ([codemode README L362–L368](https://github.com/earendil-works/pi/blob/v1.3.0/packages/codemode/README.md?plain=1#L362-L368)). `memoryLimitBytes` caps the heap; `acquireWorker()` enforces admission; aborts "request worker termination without waiting for the worker to exit" (L60–L78). Output is capped at 16 Mi characters and 100,000 items (L356).
- The sandbox isolates the script, not the tools: anything a script calls has the tool's full power [INFERENCE]. Completed effects are not rolled back when a script fails.

### 4.6 MCP

- Protocol: "MCP protocol version `2025-11-25`, accepting servers that negotiate `2025-06-18`, `2025-03-26`, or `2024-11-05`" ([README L118](https://github.com/earendil-works/pi/blob/v1.3.0/packages/mcp/README.md?plain=1#L118); [types.ts L4–L9](https://github.com/earendil-works/pi/blob/v1.3.0/packages/mcp/src/protocol/types.ts#L4-L9)). The client throws when a server selects a version outside that list (`dist/client.js`), so a server that speaks only `2026-07-28` cannot connect [INFERENCE from the code]. The client already accepts the 2026-07-28 rule that `structuredContent` may be any JSON value.
- Supported: tools, structured content, progress with timeout renewal, cancellation, Streamable HTTP with resumption, stdio shutdown applied "to the server's whole process group", `roots/list`, tool-list-change notifications, and OAuth discovery, PKCE, dynamic client registration, shared token refresh and step-up. "Batch JSON-RPC messages, legacy HTTP+SSE, servers, sampling, and tasks are outside the initial core" ([README L116–L132](https://github.com/earendil-works/pi/blob/v1.3.0/packages/mcp/README.md?plain=1#L116-L132)).
- Resources: `listResources`, `listResourceTemplates` and `readResource` are typed; subscriptions are not, but the generic `request()` and `onNotification()` methods exist (`dist/client.d.ts`). Resource subscriptions ([05 open question 4](../plan/05-bots-and-assistant.md)) are therefore possible only through the generic API and only where a server offers them [INFERENCE].
- Host duties: "Fetch can be injected for proxying" (L28), so HTTP connectors can use the egress gateway. "The package does not open a browser or choose where credentials are stored" (L110).
- Tool annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) are typed (`dist/protocol/types.d.ts`). They are server claims, so policy may use them only to add friction ([D9](../plan/decisions.md#d9)) [INFERENCE].

### 4.7 Dynamic instructions and memory

- "The system prompt is built from the selected extensions' sections, rendered in order before each request. … Sections and tool changes are stored as positional system entries in the transcript. Only what changed is sent again … A section that returns something different every time, such as the current time, defeats that" ([System Prompt, L274–L282](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L274-L282)). Identity and standing memory can therefore render from Memoshi's records on every request, which is how [D7](../plan/decisions.md#d7) is met.
- A conversation's `instructions` live in `pi.agent` and "render last". "The model, prompt, and offered tools of a request are fixed when it is prepared; a change applies from the next request" ([L282–L305](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L282-L305)).
- `beforeRequest` runs "before every request attempt, including recovery; the result is used for that request only" ([spec L2718–L2724](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L2718-L2724)). Per-turn recall and the clock belong there, and the hook reruns on recovery.
- Caching on Anthropic: pi-ai places `cache_control` on the system prompt ([anthropic-messages.ts L1244–L1249](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/src/api/anthropic-messages.ts#L1244-L1249)), on the last tool ([L1659](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/src/api/anthropic-messages.ts#L1659)), and on the last block of the final user or system message ([L1529–L1555](https://github.com/earendil-works/pi/blob/v1.3.0/packages/ai/src/api/anthropic-messages.ts#L1529-L1555)); the sibling memory research reported the same placement. A volatile block appended at the tail moves that last breakpoint on every request; its cost is the open placement question in [04 open question 8](../plan/04-architecture.md#open-questions) [INFERENCE; measure in S1].
- Compaction: defaults `reserveTokens` 16384, `keepRecentTokens` 20000, `backgroundTokens` 32768; one compact-and-retry on overflow; summaries in `pi.compaction` entries; older entries stay stored ([L454–L486](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L454-L486)). Summarization requests use `cacheRetention: "none"` ([spec L4310–L4311](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L4310-L4311)). `beforeCompact` can only decline or supply a summary ([spec L2752–L2769](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L2752-L2769)).
- **No memory system and no context-file loader in pi-durable.** The published `dist/` mentions `AGENTS.md` and skills only inside the env conformance test file (searched). Memory scopes, recall, consolidation and AGENTS.md loading are Memoshi's ([D22](../plan/decisions.md#d22), [07-coding](../plan/07-coding.md)).
- App state can live in typed documents committed with entries; `HarnessOptions.conversationCreated` runs "in every commit that creates or forks a conversation, including a tool's raw `tx.createConversation()`" ([Your Own State, L624–L646](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L624-L646)).

### 4.8 Environment adapter

- `env` "builds the execution environment for each tool call, section rendering, and `runtime.env()`" from the conversation id, its agent `cwd` and committed reads. "A throw from `env` becomes the call's error result. Without an environment, the built-in tools fail with an error result" ([Environment, L331–L345](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L331-L345); type at [types.ts L582](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/src/harness/types.ts#L582)).
- `FileSystem.id` defines the file namespace: "Every local Node environment shares one id; each container or remote host has its own" ([env/index.ts L211](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/src/env/index.ts#L211)). `edit` and `write` serialize by `id` and path.
- **Which env for which computer:**
  - `NodeExecutionEnv` "gives tools access to your local files" ([announcement](https://earendil.com/posts/pi-durable/), "Long runs anywhere"). It calls `node:fs/promises` and `node:child_process` directly and has `id = "node:local"` (`dist/env/node.js`), so file operations and commands run in the host process, and Pi "runs with the permissions of the user and process that launched it" ([root README L88–L96](https://github.com/earendil-works/pi/blob/v1.3.0/README.md?plain=1#L88-L96)).
  - `LocalExecutionEnv` "is `NodeExecutionEnv` plus `listFiles` through a daemon on the same machine" ([pi-env README L41](https://github.com/earendil-works/pi/blob/v1.3.0/packages/env/README.md?plain=1#L41)); per that description, its file operations also run in the host process. It is **not** a sandboxed This Mac.
  - `RemoteExecutionEnv` over a `Connection` sends files, exec and PTY to the daemon. `Connection.command` is the command "before its `serve --token <hex>` arguments" ([connection.ts L68](https://github.com/earendil-works/pi/blob/v1.3.0/packages/env/src/connection.ts#L68)), which is what lets Memoshi start the daemon under `sandbox-runtime` ([D16](../plan/decisions.md#d16)).
- SSH: `BatchMode`, strict host-key checking against the application's own known-hosts file under a fixed alias, no forwarding, and a daemon "named by its SHA-256 and verified before every start" ([pi-env README L20–L34](https://github.com/earendil-works/pi/blob/v1.3.0/packages/env/README.md?plain=1#L20-L34)). PTYs are "not supported on Windows yet" (L53–L56).
- Wire limits: frames up to 16 MiB; command output pauses above 4 MiB unsent; handles capped at 4096 ([protocol.md](https://github.com/earendil-works/pi/blob/v1.3.0/packages/env/docs/protocol.md)).
- `bash` defaults to `inheritEnv: true` ([bash.ts L76](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/src/tools/bash.ts#L76)); Memoshi sets it false ([07-coding](../plan/07-coding.md)).
- Gondolin's Pi extension replaces the **coding agent's** tool operations (`ReadOperations`, `BashOperations` and so on from `@earendil-works/pi-coding-agent`; [pi-gondolin.ts L28–L41](https://github.com/earendil-works/gondolin/blob/v0.13.0/host/examples/pi-gondolin.ts#L28-L41)). It is not a Durable `ExecutionEnv`.

### 4.9 Observation and the UI protocol

- Everything a UI needs is committed state, observed in-process ([Watching a Conversation, L378–L406](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L378-L406)):
  - `viewState()`: a read-only Chord state of entries, `pi.live`, `pi.inbox`, `pi.usage`, `pi.agent`, `pi.provider`;
  - `watch()`: the exact Chord operations of each commit. "A slow watch keeps at most 100 undelivered frames … A client that joins late or reconnects starts from the current view; nothing is replayed";
  - `watchEvents()` (experimental): coding-agent-style events derived from commits, with a fresh `snapshot` after falling "more than 100 batches behind" ([L488–L502](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L488-L502)). Event types in `dist/harness/events.d.ts`: `snapshot`, `run_start`, `run_end`, `turn_start`, `turn_end`, `message_start`, `message_update`, `message_end`, `tool_execution_start`, `tool_execution_update`, `tool_execution_end`, `compaction_start`, `compaction_end`, `auto_retry_start`, `auto_retry_end`, `deferred_poll`, `inbox_update`, `agent_changed`, `usage_changed`, `entry_appended`, `submission`, `task_failed`;
  - `taskGraph()`, `documentState()`, `inspect()`.
- "There is no public semantic event channel; current UI status is document state" ([spec L2702–L2703](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L2702-L2703)).
- **No published network protocol.** The experimental server, client and plugin stack was removed in 1.2.0 (§8). Chord can carry state over WebSocket links, but there is no Swift client [INFERENCE]. Earendil's own web UI exists only as private bundles (§2.2).
- So Memoshi keeps its own JSON-RPC protocol and event log with sequence numbers and replay ([D13](../plan/decisions.md#d13), [D14](../plan/decisions.md#d14)). The adapter maps Pi views and events into it and re-derives durable facts from committed entries.

### 4.10 Tasks, subagents, background work and time

- Ownership tree: aborting a call aborts the child it owns; "The parent is idle only once the child is"; a `background: true` task "survives the parent's abort and does not keep the parent busy" ([L570–L579](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L570-L579)). Examples 22 (foreground subagent) and 23 (persistent subagents with restart-safe reporters) are the patterns [04 §4.6](../plan/04-architecture.md#46-tasks-subagents-handoffs-and-runs) adopts.
- Child tasks can wait with `allSettled` or `failFast`; abort runs bottom-up so "each task undoes its own effects" ([L581–L606](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L581-L606)).
- Time: 1.3.0 offers `TaskRuntime.sleep(until)`, a wait inside a phase ([spec L1782, L1867–L1870](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L1867-L1870)). There is no calendar, recurrence, quiet-hours or missed-run logic. Earendil's own sample writes its own time-zone-aware recurrence inside a Durable task ([`src/schedule.ts`](https://github.com/earendil-works/pi-durable-cloudflare/blob/main/src/schedule.ts)). Routines, wakes and watches stay in memoshid's scheduler ([05](../plan/05-bots-and-assistant.md)).

### 4.11 Errors

"A storage error ends the Harness"; "An invalid request fails only that call"; "Your code fails only its own unit … a throwing hook is reported and skipped (`beforeTool` blocks the call)". `harness.closed` settles with `{ reason: "failed" }`, and a reopen plus the same `requestId` finds admitted work ([Errors, L711–L727](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/README.md?plain=1#L711-L727)). In 1.3.0, `onReport` takes one argument (`dist/harness/types.d.ts`).

### 4.12 Holding work for an explicit Resume (D42)

- **Scheduling is per Harness.** "`resume()` … only enables scheduling. … Calls that ask for progress also enable scheduling …: `Conversation.submit()`, `Conversation.compact()`, `Conversation.abort()`, `Submission.wait()`, `Harness.waitForTask()`, `Harness.waitForIdle()`, and `Conversation.waitForIdle()`. Recovered work starts with them. A viewer that only reads never enables scheduling" ([spec L669–L678](https://github.com/earendil-works/pi/blob/v1.3.0/packages/durable/docs/spec.md?plain=1#L669-L678)). `inspect()` reports `scheduling: "paused" | "running" | "closing"` (L557–L558). There is no per-task or per-conversation pause in 1.3.0.
- **Aiden's working answer:** one Harness per bot, and "Recovery is explicit. Opening and inspecting a harness never starts its task scheduler: this module never calls `resume()`, `submit()`, `wait*()` or anything else that asks for progress … Interrupted work stays paused until the user chooses Resume" ([harness-host.ts L1–L12 at `2b085b6`](https://github.com/sambitcreate/aiden-agent/blob/2b085b6aaa1ece8550580a8739730f4f800f5ec5/main/services/bot-runtime/harness-host.ts#L1-L12)).
- **Consequences for Memoshi** [INFERENCE from the verified rules]:
  - With one Pi file per thread ([A1](../plan/04-architecture.md#0-what-this-document-adds-to-the-contract)), a file-level hold holds the whole thread: Chat, routine runs and Handoff lanes together. The plan's wish that "the rest of its thread file resumes" ([04 §4.11](../plan/04-architecture.md#411-replay-and-idempotency)) is not available at file level.
  - Any user message into a held thread is a `submit()` and resumes everything recovered in that file.
  - Safe mode ([04 §2.3](../plan/04-architecture.md#23-lifecycle)) must avoid all progress calls, not just `resume()`. A "Stop all bots" `abort()` enables scheduling for its Harness, and background tasks survive a plain abort unless `{ background: true }` is passed.
- **Options for S1.13** ([04 open question 10](../plan/04-architecture.md#open-questions)):
  1. File-level hold (Aiden): simple and verified, but coarse.
  2. A memo-keyed wait in `beforeRequest` or `beforeTool`: per conversation and per call, but it holds a task invocation in memory, and it cannot stop recovery from committing `interrupted` results for unsafe tools (which is safe, since nothing reruns).
  3. **Unreleased:** a crash-loop guard that parks tasks after `settings.restartLimit` restarts (default 5), plus `Harness.retryTask(id)` (§7). With a low limit this could become a per-task hold. It needs re-verification once released.

2. **Treat the next Pi release as a migration, not a bump.** Back up Pi files before the first open; run C1–C20, the chaos suite and the tests below; then re-decide the D42 hold, the scheduler split and `onWake` against the released text.
3. **Keep the adapter rules in [04](../plan/04-architecture.md)**, which this check confirms: identity rendered through sections, never `root()` options; volatile context in `beforeRequest`; the policy extension last; memo-keyed approvals; an `afterTool` scrubber that catches its own errors and redacts `structuredOutput`; `RemoteExecutionEnv` for every computer, never `NodeExecutionEnv` or `LocalExecutionEnv` for a confined one; `inheritEnv: false`; Code Mode with `models: false`, an `acquireWorker` limit and explicit `wasm` and `workerUrl`; MCP tools wrapped as deferred Durable tools, with annotations used only to add friction.
4. **Add contract tests** [INFERENCE: proposed, not yet in the plan]:
   - progress calls (`submit`, `abort`, `compact`, waits) enable scheduling, and safe mode makes none of them;
   - a pi-env connection lost during a mutating call yields an unknown outcome and a Resume card, never an automatic retry;
   - the credential store rejects `oauth` credentials, and the launcher strips OAuth-token variables;
   - the bundle contains no pi-ai OAuth flow module, and the license manifest takes Pi's MIT text from the repository.
5. **Ecosystem use:** port Gondolin's egress and placeholder design with Apache-2.0 attribution, planning for its HTTP/1.x limit; read `pi-durable-components`' presentation contract and Aiden's `harness-host.ts` (both MIT) as references; read `pi-durable-cloudflare` for scheduling inside a task and multi-client views.
6. **Keep Memoshi's own responsibilities explicit** (§6): policy, approvals and Cards, scheduler, memory, effects ledger, protocol and event log, sandboxing and egress, the Apple capability broker, and process lifecycle.
