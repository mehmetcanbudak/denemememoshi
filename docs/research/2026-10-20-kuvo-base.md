## Decision

**Historical decision (2026-10-20): source/fork restrictions superseded by the D91 amendment above.**

**Use Kuvo as the native workspace and interaction reference, not as the repository to fork.** This follows the user's existing clean-build decision [D43](../plan/decisions.md#d43). The new request for a Kuvo + Grok combination does not itself remove that decision or the licence constraint.

Kuvo's site advertises SwiftUI + AppKit, no Electron or web view for the interface, Apple-silicon macOS 26+, and the unmodified opencode engine. The site links v0.5.22. This is a public documentation observation, not a binary audit. Pi therefore replaces the **engine role**, not merely a model-provider entry in Kuvo's settings. [Product page](https://www.kuvo.run/code/)

## Verified public behaviour

| Area | Documented behaviour | Memoshi use |
|---|---|---|
| Window | Sidebar for bots/groups/chats/projects, central conversation, right side panel; session tabs; collapsible panes and side-by-side sessions | Keep the workbench structure; retain Memoshi's existing Chat versus Session vocabulary |
| Projects | Multiple granted folders; sessions run in the primary folder; local or SSH-hosted projects | A workspace is a real execution context, not a chat label |
| Review | Git-backed changes, staged/unstaged/branch/session views, image comparisons, inline line comments sent with the next message, commit and PR workflow | Make review the completion path for coding tasks |
| Concurrency | Worktree per session; parallel Attempts; setup command; cleanup does not silently remove active or unreviewed work | Adopt worktree ownership and explicit cleanup; a worktree is not a security sandbox |
| Conversation | Steer versus queue, explicit stop/resume, context usage, fork, transcript export, inspectable subagent/tool activity | One transcript projection across personal assistant and coding work |
| Bots | Persistent identity, one job, memory file, wake-ups, model-free watches, per-bot browser tabs | Preserve clear job/state/proactivity rather than adding many interchangeable personas |
| Groups | One speaker at a time, lead summary, dependency-aware work assignments, execution in each bot's conversation, reports back to the group | Discussion and execution are separate; retain bounded Handoffs |
| Browser | Visible WebKit panel on Mac; remote browser on execution machine; numbered-element actions; Take Over/Hand Back | Prefer structured browser actions over screenshots when possible |
| Sign-in | Credentials filled directly into current verified page; stale site/field check; CAPTCHA/manual intervention cards | Design reference for secret handling, not an independently audited no-leak guarantee |
| Background work | Local bots work while the Mac is awake; SSH-hosted bots can work while the Mac is off; group meetings depend on the app being open | Make execution location and availability explicit in every task |
| Native surfaces | Keyboard shortcuts, Dock actions, menu-bar usage, actionable notifications, file dropping/Quick Look-style workflow | Keep desktop ergonomics, not a web-chat wrapper |

## What not to copy

- **Approve All as the default.** Sessions documentation says it is the default and can override rules configured as Ask First. Memoshi keeps its own external policy engine, explicit grants and draft-before-send. [Sessions](https://www.kuvo.run/code/docs/sessions/)
- **A memory file as the entire trust model.** Kuvo documents readable per-bot memory; Memoshi already specifies scopes, evidence, revision history and invalidation. [Bots](https://www.kuvo.run/code/docs/bots/), [Memoshi memory](../plan/05-bots-and-assistant.md#5-memory-governance)
- **Worktrees as isolation.** The documented workspace separation protects checkouts, not the operating system or secrets. Memoshi's sandbox/VM policy is a separate requirement. [Sessions](https://www.kuvo.run/code/docs/sessions/#worktrees), [Memoshi computers](../plan/06-computers-and-browsers.md)
- **Opt-out usage analytics.** The website says anonymous usage can be disabled; Memoshi's current decision is telemetry off by default. [Product FAQ](https://www.kuvo.run/code/), [D28](../plan/decisions.md#d28)

## Licence and clean-room limits

**Historical policy context (2026-10-20): the no-source/no-fork/separate-observer rule below is superseded by D91. The recorded licence observations and visual-rights caution are not rewritten.**

The current [LICENSE](https://github.com/serhatandic/kuvo-code/blob/main/LICENSE) is **PolyForm Noncommercial 1.0.0**, not an OSI open-source licence. Its personal-use provision refers to uses without anticipated commercial application. The product FAQ says commercial use, including use at work, needs a paid licence. A public GitHub repository does not establish permission to turn it into a commercially distributed Pi product.

Memoshi's existing rule is stricter and remains unchanged: no Kuvo code, text or assets; no fork; observers and builders separated; captures outside this repo. The existing decision also records a design-law risk for exact visual parity. A clean-room implementation is not a legal guarantee. [D33](../plan/decisions.md#d33), [D43](../plan/decisions.md#d43)

## Fit with the newly requested Apple-native direction

[INFERENCE] Kuvo supplies the **workbench grammar**: navigation, sessions, review, files, terminal, browser and task visibility. The Viticci examples should supply the **personal-action grammar**: actual Reminders/Calendar/Music resources, editable native controls, object state and direct actions. These are complementary layers; neither requires replacing Pi.

Preserve the distinction between an immutable approval/receipt and a live resource view. A checked reminder must update the real reminder, not just change a Markdown checkbox. Likewise, a music card should report playback state from the player, not infer it from a model's answer. The [next-version proposal](../plan/NEXT_VERSION.md) specifies that combination; it does not claim it exists in Kuvo or Memoshi today.
