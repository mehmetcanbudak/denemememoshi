## 1. How to use this register

**Likelihood (L)** is the chance the risk materializes before the v1.0 gate, M3 ([calendar](10-roadmap.md#calendar), [D122](decisions.md#d122)). Risks marked with a later stage (the end of Phase 2, Phase 3, Drop 1, Drop 2 or v1.1; [D87](decisions.md#d87), [D117](decisions.md#d117)) are scored for the work they belong to:

| Level | Meaning |
|---|---|
| **H** | More likely than not (> 60%) |
| **M** | Plausible (20–60%) |
| **L** | Unlikely (< 20%) |

**Impact (I)** is what happens if it does:

| Level | Meaning |
|---|---|
| **H** | More than 3 weeks of slip, a broken v1 promise ([MASTER_PLAN §1](MASTER_PLAN.md#1-the-product)), or user harm: data loss, a security incident, or unexpected spend |
| **M** | 1–3 weeks of slip, or a feature moved down the [cut order](10-roadmap.md#cut-order) |
| **L** | Under a week, or a quality issue that a later phase absorbs |

**Score** = L × I with H = 3, M = 2, L = 1. Scores of 6 or more are reviewed weekly; every risk is re-scored at each [phase gate](10-roadmap.md#gate-template). A risk that materializes becomes an issue in the tracker, and its row records the date.

**Owners** are the plan's hats ([D45](decisions.md#d45)). One builder wears them all, with coding agents; the code says which kind of work a risk belongs to:

| Code | Hat | Typical risks |
|---|---|---|
| **PD** | Product and design | Scope, cut order, names, vendor policy, market |
| **EL** | Engineering lead | Cross-cutting technical risk, licensing, vendors, the hosted relay |
| **RT** | Runtime (Swift) | The engine and Pi_Swift integration: policy, scheduler, memory, stores, leases and replicas |
| **APP** | App (Swift) | Shell, conversation, design system, UI performance |
| **NAT** | Native services (Swift) | Computer, Browser and Apple services, iPhone and iPad platform, packaging and signing |
| **QA** | QA and automation | Chaos, smoke, red-team and release harnesses |

The owner keeps the mitigation moving and reports the early signal.

### New questions raised by this register

1. **Where does the Bot computer image come from (Phase 2)?** Download on first use (about 3 GB compressed) from static hosting, or build locally from Debian packages? Either way, [D39](decisions.md#d39) counts static distribution hosting, including signed Bot computer images, as allowed (A17). [D113](decisions.md#d113) requires the image's sources to be published ([D83](decisions.md#d83)). Owner: NAT with [06-computers-and-browsers.md](06-computers-and-browsers.md).
2. **Which Node LTS line would the Mac fallback ship?** Only if the Mac misses the Pi_Swift gate ([D46](decisions.md#d46)). Node 24 is in maintenance from 2026-10-20 to 2028-04-30; Node 26 becomes LTS on 2026-10-28 and is supported until 2029-04-30; [D15](decisions.md#d15) prefers 26 (R3, R39).
3. **Do Macs with 8 GB of RAM get Bot computers at all (Phase 2)?** O4 sets the cap; this question sets the floor. [09-platform-macos.md](09-platform-macos.md) proposes one awake "compact" VM (2 vCPU / 2 GB) by explicit opt-in on 8 GB Macs; the VM spike measures it on the 8 GB machine. Since [D113](decisions.md#d113) a bot on such a Mac can also be given a Cloud computer (R20, R67, A5).
4. **Who performs the external security review, and when is it booked?** SEC-21 includes an external review; it needs a budget and a vendor slot in Phase 4, so it should be booked by the Phase 2 gate (M2). Since [D117](decisions.md#d117) the review also covers mail, Apps, voice and bot computers (R6, R28, R38, R65, R66, R69).
5. **What monthly cap does the dogfood budget use?** Settled by [D86](decisions.md#d86): $300 a month until M2.1, then a larger cap the user sets for coding inside Memoshi (R11).
6. **Do alpha testers need more than the budget floor?** The friendly alpha is optional ([D67](decisions.md#d67)). If it runs, it starts before full Budgets ship in Phase 3, so testers get only the budget floor (RT-12, BU-07) (R23).
7. **Should user-facing backup and restore (EXP-04) rise from P2?** It is the only restore path for users before the full export (EXP-06); with stores on every device, replicas and browser profiles in v1, a P1 rating would protect it from the first cut level (R15).
8. **When is the CloudKit container named?** Settled by [D59](decisions.md#d59): `iCloud.com.mehmetcanbudak.memoshi`, created in Phase 0 and kept whatever the product's final name (R22).
9. **Is P0-19's design-reference spec re-based on Cognitio before the Phase 0 gate?** Settled on 2026-11-13: no. The Phase 0 exit deliverable stays the spec v0 that exists in [design-reference.md](../specs/design-reference.md), written Viticci-led and Kuvo-informed and kept as the record; since [D106](decisions.md#d106) its direction section makes Cognitio's design the lead, and the behaviour descriptions are Phase 1 work (R14).
10. **Who writes each surface's behaviour description from Cognitio, and when?** [D106](decisions.md#d106) requires one before a surface is built, and [amendment §8](AMENDMENT_2026-11-13.md#8-open-items) (item 11) leaves the author to the design review; the descriptions are Phase 1 work, each written before its surface is built (R14, R63, R64).
11. **Where is the builder's time on Cognitio counted?** [D107](decisions.md#d107) says the roadmap review counts the two live codebases, and [D122](decisions.md#d122)'s item sizing has no line for Cognitio's own work [INFERENCE: read from the sizing]. Until a gate review says otherwise it shows only in the weekly burn-up (R63, R47, A25).
12. **What meets M2's own-computer exit if the VM spike fails?** R20 starts the Bot computer work only if the spike passed, while M2's exit has a bot finishing a web chore in its own computer while watched ([amendment §3](AMENDMENT_2026-11-13.md#3-milestones)). The catalog ties that exit to Chromium in a Bot computer (BRW-11) and rates Cloud computers (V2-02) P1. Whether a Cloud computer alone meets the exit is not decided; it is settled with the spike, CMP-01 (R20, R67).
13. **How do plugins in plugin developer mode reach a separate helper?** Pi_Swift's loader compiles and loads Swift in-process today, and [D114](decisions.md#d114) requires a separate helper process, never memoshid or the app. The interface is Phase 2 design work for CH-44 ([amendment §8](AMENDMENT_2026-11-13.md#8-open-items), item 10) (R66, R39).
14. **Do Claude Code's terms and the mail providers' reviews allow a public release?** Both are checked before O13 ([amendment §8](AMENDMENT_2026-11-13.md#8-open-items), items 8 and 9). That Gmail and Microsoft review apps that read mail is [INFERENCE: from general knowledge; verify] (R68, A26, A27).
15. **What is the on-device voice target, and which defaults survive measurement?** [D111](decisions.md#d111) sets the on-device engine's target by measurement, and [D120](decisions.md#d120) gives each default provider (web search, cloud voice, the on-device voice, image and video, Cloud computer) a short measured comparison before the phase that ships it (R69, R67, R68, A28, A29).
